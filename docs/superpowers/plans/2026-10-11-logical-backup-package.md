# Logical Backup Package Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add an internal, deterministic logical-package format with bounded writer/validator and JVM fixture round-trip tests, without connecting user data or exposing export.

**Architecture:** Keep the package contract and validator as pure Kotlin domain code. A ZIP writer serializes only explicitly supplied logical records and resource byte streams, then the validator independently re-reads the generated bytes. Tests use synthetic fixtures only; production Room, media storage, SAF, UI, Hilt, and device data remain disconnected.

**Tech Stack:** Kotlin, JDK `ZipOutputStream`/`ZipInputStream`, kotlinx.serialization JSON already present in the version catalog, JUnit 5.

**Spec:** `docs/superpowers/specs/2026-10-11-logical-backup-export-design.md`; project constraints in `AGENTS.md` and `docs/specs/04-history-reminders-backup-and-security.md`.

## Global Constraints

- This plan is only an internal test-format foundation; it does not implement user-visible export, backup encryption, signature, pairing, import, restore, or data replacement.
- Tests must use synthetic profiles and in-memory resource bytes; production Room DAOs and private media stores must never be referenced.
- A SHA-256 digest detects accidental corruption only; it is not authentication, a signature, or tamper protection.
- API Keys, Authorization headers, Keystore materials, system TTS audio, temporary images, logs, and bundled Kokoro/model assets are excluded by construction.
- No test may write a user backup file or connect to a real database/device.
- Follow project TDD: RED → minimal GREEN → focused regression; do not commit or push without explicit authorization.

## Interfaces

Task 1 defines and freezes these APIs for later tasks:

```kotlin
object BackupPackageFormat {
    const val CURRENT_VERSION: Int = 1
    val DefaultLimits: PackageLimits
}

data class PackageLimits(
    val maxArchiveBytes: Long,
    val maxEntries: Int,
    val maxEntryBytes: Long,
    val maxTotalBytes: Long,
)

object BackupPackageLimits {
    const val MAX_ARCHIVE_BYTES: Long = 268_435_456L
    const val MAX_ENTRIES: Int = 10_000
    const val MAX_ENTRY_BYTES: Long = 67_108_864L
    const val MAX_TOTAL_BYTES: Long = 1_073_741_824L
}

data class PackageEntry(
    val path: String,
    val byteSize: Long,
    val sha256: String,
)

data class PackageManifest(
    val formatVersion: Int,
    val entries: List<PackageEntry>,
    val payloadSha256: String,
)

sealed interface PackageValidationFailure {
    data object InvalidArchive : PackageValidationFailure
    data object InvalidManifest : PackageValidationFailure
    data object UnsupportedFormat : PackageValidationFailure
    data object InvalidPath : PackageValidationFailure
    data object DuplicateEntry : PackageValidationFailure
    data object LimitExceeded : PackageValidationFailure
    data object LengthMismatch : PackageValidationFailure
    data object IntegrityFailure : PackageValidationFailure
}

sealed interface PackageValidationResult {
    data class Valid(val manifest: PackageManifest) : PackageValidationResult
    data class Invalid(val reason: PackageValidationFailure) : PackageValidationResult
}

class BackupPackageValidator(
    private val limits: PackageLimits = BackupPackageFormat.DefaultLimits,
    private val json: Json = Json,
) {
    fun validate(bytes: ByteArray): PackageValidationResult
    fun readEntries(bytes: ByteArray): PackageReadResult
}

sealed interface PackageReadResult {
    data class Read(val entries: Map<String, ByteArray>) : PackageReadResult
    data class Invalid(val reason: PackageValidationFailure) : PackageReadResult
}
```

Both methods reject `bytes.size > maxArchiveBytes` before parsing. `readEntries` first validates the entire archive, then returns copied payload entries excluding `manifest.json`; no partially validated entries escape. The writer API is fixed in Task 3 after its test first specifies ordering and stream behavior. It must return bytes in memory for JVM fixture tests and must not write files.

## Self-Review / Known Limits

- Spec coverage for this internal subproject: versioned package contract, allowlisted paths/record kinds, deterministic writer, manifest, bounded validator, digest checks, malformed/hostile ZIP rejection, credential-free closed types, and synthetic round-trip are covered by Tasks 1–5.
- Explicitly excluded: real snapshot collection, all F4 record domains, SAF export, UI, device export, signature, AEAD/KDF, pairing, restore, and AC4-03/04/05 completion claims.
- ZIP metadata determinism and bounded decompression behavior must be proven by tests; if the JDK ZIP implementation cannot satisfy the selected stable encoding or resource limits, stop and revise this plan before introducing dependencies.
- This plan does not authorize implementation by itself. The design document must be reviewed/approved first; then execute using `superpowers:executing-plans` with per-task checkpoints.
