# Android AI 英语背词应用功能需求文档（PRD）

- **版本**：V1.0
- **状态**：待评审
- **平台**：Android 手机
- **产品定位**：本地优先、面向全人群的英语背词与语境复习应用；首要服务大学生、四六级与考研用户。

---

## 1. 产品愿景与目标

### 1.1 产品愿景

让用户以“选词书—定目标—背单词—间隔复习—读 AI 生成短文—查词/翻译巩固”的日常闭环高效积累英语词汇。应用不要求注册账号，学习核心可离线使用，用户自行掌握学习数据与 AI 服务配置。

### 1.2 V1 成功标准

1. 用户可完成选择词书、设置每日目标、学习新词、完成到期复习、解锁阅读短文的完整闭环。
2. 当日学习完成后，用户可按文章类型生成与当天已完成词汇相关的英文短文，阅读页可查看全文翻译、高亮词义和发音。
3. 用户可在后续日期按照间隔复习队列继续学习，切换词书后仍保留各词书独立进度。
4. 用户可以不登录使用；导出后可在另一台设备通过旧设备配对认证、完整性校验和可选密码安全恢复学习数据。
5. AI 服务不可用、网络中断或未配置 API Key 时，不影响背词、复习、历史文章阅读与系统离线发音。

### 1.3 非目标

- V1 不提供完整的语法、听力、口语课程，亦不提供社交、排行、商城、教师端或云端账号同步。
- V1 不承诺 AI 文章覆盖当天每一个词；必须如实展示未覆盖词汇。
- V1 不以 AI 内容替代权威考试资料、专业翻译或真实新闻来源。
- V1 不保存、不导出、不恢复用户 API Key、设备密钥或云端服务令牌。

## 2. 用户与使用场景

### 2.1 目标用户

- **核心用户**：大学生、大学英语四级/六级及考研备考用户。
- **通用用户**：小学、初中、高中、日常英语、职场英语等不同学习阶段的人群。
- **共同特征**：每天可投入 10–30 分钟；希望看到明确进度，需要中文释义和标准英语发音；注重资料与进度可控、可迁移。

### 2.2 关键场景

1. **首次建档**：用户选定词书与每日新词目标，进入今日学习页。
2. **每日学习**：用户先完成今日到期复习，再完成新词卡片，通过三档反馈确定后续复习时间。
3. **文章巩固**：满足解锁规则后，选择新闻、故事、科普或职场类型，生成短文并在阅读中复习当天词。
4. **即时辅助**：用户随时查词、听发音，或拍照识别英文后进行翻译和查词。
5. **换机迁移**：旧设备导出备份并生成一次性配对码/二维码；新设备完成配对、校验与可选密码验证后恢复。

## 4. 详细功能需求

### FR-01 词书、学习档案与每日计划

1. 首次使用时必须选择一个词书并设置有效每日新词目标；每日新词目标最小值为 1。
2. V1 内置词书至少包含：小学、初中、高中、大学四级、大学六级、考研词汇。后续可扩展雅思、托福、商务和自定义词书。
3. 词书列表展示名称、适用阶段、总词量、已学数量与学习进度。
4. 同一用户可启用多个词书；每本词书维护独立的单词进度、复习状态与完成记录。首页只有一个当前活动词书。
5. 今日计划在首次进入学习时按本地自然日生成快照，包含：到期复习词集合、计划新词集合、词书、解锁规则与目标数量。
6. 默认学习顺序为“到期复习优先，再学习新词”；界面必须分别展示两类任务及剩余数量。
7. 修改每日新词目标、活动词书或完成规则默认从次日计划生效；当天计划尚未开始时，用户可明确选择“重新生成今日计划”。已提交反馈后不可静默重建。
8. 词书剩余新词少于目标时，以实际剩余数量作为当日新词计划；完成全部可用新词和当日复习后可正常完成。

### FR-02 单词卡片与三档反馈

1. 每张词卡至少显示英文单词、IPA/音标、词性、中文释义；有资源时显示词形变化、例句和例句翻译。
2. 每张词卡提供发音按钮；用户可选择系统 TTS、端侧离线语音或 AI 语音作为默认发音来源。
3. 用户完成一次反馈后，该单词才计入本次新词学习或复习完成。反馈只有三档：**不认识、模糊、认识**。
4. “不认识、模糊、认识”分别映射为由复习调度策略定义的低、中、高记忆评分，保证下一次复习时间满足：不认识不晚于模糊，模糊不晚于认识。
5. 系统使用 FSRS 兼容调度策略计算后续复习，必须保存学习事件、反馈、发生时间、调度前后状态和下次复习时间；算法或参数升级只能重算未来安排，不得篡改历史事件。
6. 反馈提交必须防重复：同一交互事件重复提交不得让完成数或复习间隔重复变化。
7. 用户中途退出时已提交的反馈即时保存，未提交反馈的词不计入完成；下次从未完成项继续。

### FR-03 每日完成与文章解锁

1. 默认严格模式：当日计划的新词与计划生成时已到期的全部复习词均完成，才判定“今日完成”。
2. 设置中提供宽松模式：完成当日计划新词即可解锁文章；到期复习仍保留为待办，但不阻塞解锁。
3. 当前解锁模式必须在首页与完成页显式可见。切换模式仅影响尚未开始或后续日期计划，历史记录不受影响。
4. 今日计划生成后，之后才新到期的单词不纳入当日完成判定，避免资格反复变化。
5. AI 请求失败、AI 未配置、网络中断不影响“今日完成”状态；仅显示文章生成失败和可重试入口。
6. 已生成的历史文章允许离线重读；未解锁时不得生成当日新文章。

### FR-04 AI 复习短文

1. 当日解锁后，用户可选择文章类型：**新闻、故事、科普、职场**；应用记录用户默认偏好。
2. 系统生成时输入当天已完成的新词与复习词、当前词书等级、文章类型、最终长度、语言偏好；输出标题、英文正文、全文中文翻译、命中词位置及未覆盖词清单。
3. 文章长度默认按词书等级控制：小学/初中 80–120 词，高中 120–180 词，四级/六级/考研 180–300 词。用户可在设置中选择简短、标准、长篇覆盖默认；最终长度配置随文章存档，后续改设置不改变历史文章。
4. 阅读页默认展示英文原文与高亮词，全文翻译可展开；用户可在设置中选择默认英文优先、双语对照或默认展开全文翻译。
5. 点击高亮词可查看词义、音标、例句并播放发音。未在正文中覆盖的当天词必须单独列出，不得伪称全部覆盖。
6. 同一日期、同一活动词书、同一类型和长度默认复用已成功生成的文章。用户可主动“换一篇”，生成新版本但保留历史版本与来源信息。
7. AI 返回内容必须经结构完整性、目标语言、长度容差、目标词标注和安全内容校验后才能保存与显示；不符合要求时不写入正式文章库。

### FR-05 AI 配置与自定义供应商

1. 应用以用户自带 API Key 为主，不提供内置 AI 免费额度。所有成本、配额和服务条款由用户与供应商自行承担。
2. 用户可创建多个 AI 供应商配置，字段包括：供应商名称、备注、官网、兼容 OpenAI 的 API 基础地址、默认模型、能力声明（文本/视觉/语音）、超时和受控高级参数。
3. V1 支持的高级参数限于温度、最大输出长度、top_p、请求超时与安全的系统提示模板；不支持任意 Header、任意 Body 覆盖或任意工具调用。后续可在明确风险提示下加入专家模式。
4. API Key 必须仅存储在 Android Keystore 支撑的安全凭据区；设置页掩码显示，支持连接测试、替换和删除。Key 不得进入数据库业务表、日志、崩溃报告、剪贴板、文章来源信息或备份文件。
5. AI 网关统一负责请求组装、参数白名单验证、HTTPS/Endpoint 合法性检查、超时、取消、错误归一化、响应结构校验和脱敏诊断。页面不得直接调用第三方 API。
6. 调用视觉模型前，应用必须告知用户图片与识别文本将发送至其配置的第三方服务；未确认不得上传。
7. 未配置、无效 Key、供应商不支持所需能力、限流、超时或网络失败时，必须说明具体可行动原因（检查配置、选择支持视觉/语音的模型、稍后重试或使用离线能力）。

### FR-06 查词、翻译与发音

1. 查词支持输入英文单词和短语；优先使用本地离线词典，展示音标、词性、中文释义、例句、词形变化和近义关系（若有）。
2. 离线词典未命中时，用户可主动调用已配置的 AI 服务补充释义或翻译；应用须标识内容来源为本地或 AI。
3. 所有可发音英文单词、例句和文章句子均提供播放入口。
4. 发音提供统一优先级：系统 Android TTS（优先离线英语包）→ 用户已安装的端侧 sherpa-onnx/Piper 英语模型 → 用户配置的 TalkifyTTS 或其他支持语音的 AI 供应商。用户可以在设置中指定默认来源。
5. 缺少系统英语离线包、端侧模型或可用 AI 语音时，应显示安装、下载、切换或重试指引，不阻塞背词。
6. AI/云端合成的音频按“规范化文本 + 语音参数 + 模型版本”缓存到本地；缓存保存 SHA-256、大小、生成时间、来源与关联词条。系统 TTS 不生成也不导出音频文件。
7. 用户可清理 AI 音频缓存；清理不删除学习进度。启用备份时，用户可选择是否包含已校验的 AI 音频资源。

### FR-07 拍照翻译

1. 用户可使用相机拍摄或从相册选择图片；应用在运行时请求并解释相机/媒体权限用途。
2. 默认使用端侧 OCR 识别英文及文本区域，主路径采用 ML Kit；无 GMS 或主路径不可用时使用 Tesseract 降级。OCR 输出须可编辑，并向用户标识低置信区域。
3. 用户确认 OCR 文本后才可发起智能翻译；翻译优先使用用户配置、声明视觉或文本翻译能力的 AI 供应商。
4. 翻译页支持原文与译文对照、选词查义、单词发音与复制；OCR 或 AI 失败时保留可编辑原文并提供重试/复制，不得导致应用崩溃。
5. 原始图片默认只短期使用，不写入历史、不进入备份；只有用户明确保存时，才保存原图、OCR 文本和译文。保存的媒体受本地存储与备份校验规则约束。
6. 图片上传至第三方 AI 前必须获得明确确认，并提示图片由用户配置的第三方服务处理。

### FR-08 历史、收藏与统计

1. 历史按日期展示词书、新词完成数、复习完成数、完成状态、解锁规则、文章生成与阅读状态。
2. 用户可重读历史文章、查看文章版本、搜索查询历史；可收藏词条、将词条加入错词本并按列表复习。
3. V1 提供基础统计：累计学习词数、累计复习数、连续学习天数、每日完成率。连续学习以完成当前选择的每日完成规则为准；阅读文章不作为连续学习必要条件。

### FR-09 本地提醒

1. 用户可启用本地提醒并设置每日提醒时间，默认关闭。
2. 到点仅在当日计划未完成时提醒“今日仍有学习/复习任务”，不得在通知内容包含 API Key、图片或敏感文本。
3. 用户拒绝通知权限、设备限制精确闹钟、设备重启或时区变化时，应用重新计算下一次提醒，并在设置页显示当前状态与解决指引。

### FR-10 备份、迁移与恢复认证

1. 用户可导出本地学习档案、词书进度、学习事件、每日计划与记录、文章、收藏/查询历史及可选 AI 音频、已保存拍照翻译历史。API Key、Android Keystore 中的密钥、系统 TTS 数据和临时图片一律不得导出。
2. 每个备份包必须包含格式版本、数据清单、资源索引、资源关系、单文件 SHA-256、整体哈希、创建时间、应用版本、签名、加密元数据和迁移认证元数据。
3. 备份认证采用：**旧设备一次性配对二维码/迁移码 + 自动完整性签名 + 用户可选备份密码**。旧设备生成的迁移凭据必须具备有效期、一次性使用与撤销机制。
4. 用户可设置备份密码。启用密码后，应用使用经验证的密钥派生和加密方案保护备份主体；忘记密码无法恢复，应用不得声称可绕过或找回密码。
5. 新设备导入先完成旧设备配对，再在隔离临时区依次验证：格式与版本、必填结构、可选密码解密、单文件/整体哈希、签名、资源清单、资源关联、磁盘空间与兼容性。
6. 任一验证失败、配对凭据无效/过期/已使用、密码错误、文件缺失、哈希不一致、签名不可信或资源关联不完整时，必须拒绝恢复、清除临时区、不修改当前本机数据，并给出不泄露敏感信息的失败原因。
7. 所有校验通过后，用户选择“替换本机数据”并进行二次确认；系统先创建本机回滚点，再在维护锁下原子替换数据库与资源文件，重建通知和缓存索引。V1 不提供合并恢复，避免复习队列与资源冲突。
8. 恢复成功后，不恢复 API Key；AI 配置显示“需要重新填写密钥”。

## 5. 数据与状态规则

### 5.1 核心数据对象

- **WordBook / Word**：词书、等级、版本、单词、义项、音标、例句与词形。
- **LearningProfile**：当前活动词书、每日目标、完成规则、时区和学习偏好。
- **WordProgress / LearningEvent**：当前掌握状态与不可变学习事件。
- **TodayPlan**：按日期生成的任务快照、规则快照、完成状态和解锁资格。
- **Article / ArticleAnnotation**：文章、翻译、类型、长度、版本、高亮词、未覆盖词与阅读进度。
- **AiProfile / SecretReference**：非敏感供应商配置和安全凭据引用；不保存 Key 明文。
- **MediaAsset / PronunciationCache**：可校验的 AI 音频及其资源引用。
- **BackupManifest**：备份版本、内容哈希、签名、加密元数据、资源索引和认证状态。

### 5.2 数据权威性

- 本地数据库与资源仓是学习进度、复习状态和文章缓存的权威来源。
- 今日完成状态只能由今日计划和学习事件计算，不能以页面展示状态为准。
- AI 输出为不可信输入，必须校验后才可持久化和渲染；渲染时不得执行 HTML、脚本或供应商返回的任意指令。

## 6. 安全、隐私与合规

1. 核心学习和离线缓存阅读不依赖网络；网络仅在用户主动使用 AI/在线能力时调用。
2. 任何自定义 AI Endpoint 均要求 HTTPS、合法 URL 校验及明确的第三方数据处理提示。
3. API Key、签名私钥和备份敏感材料使用 Android Keystore 及安全凭据区保护；不得以明文出现在日志、诊断、截图、剪贴板、备份或导出文件。
4. AI 图像上传必须获得用户单次明确确认；拍照原图默认不保存。
5. 用户可分别清除学习数据、文章与媒体缓存、已保存拍照历史、AI 配置；破坏性清除操作必须二次确认。
6. 所有第三方依赖、词典数据和模型必须登记版本、许可证、用途、隐私数据流、署名位置和替代方案；发布前完成许可证与服务条款审查。
7. 不将 GPL-3.0 组件静态整合进闭源主应用；不得在商业版本使用标注为非商业用途的语音模型。

| 领域 | 推荐方案 | 许可证/注意事项 |
|---|---|---|
| 复习调度 | FSRS Kotlin 实现 | 建议 MIT；锁定算法版本，保留策略边界与原始事件 |
| 本地数据库 | Room | AndroidX / Apache-2.0；用于关系数据与事务 |
| 安全存储 | Android Keystore；可选 SQLCipher | Key 隔离；SQLCipher 需单独评估性能与许可 |
| 本地词典 | OpenLeaf-Dictionary SQLite 或等价 Wiktionary 衍生数据 | CC BY-SA 4.0；落实署名、许可副本、来源链接及数据改编审查 |
| OCR | Google ML Kit 主路径 + Tesseract 降级 | ML Kit 依赖 GMS；Tesseract 为无 GMS 兜底 |
| 系统发音 | Android TextToSpeech | 依赖设备语音引擎与英语离线包 |
| 端侧高质量发音 | sherpa-onnx + Piper 英语模型 | 引擎与每个模型许可必须分别审核；模型按需下载并可清理 |
| 在线高质量发音 | TalkifyTTS 或用户自定义 AI TTS Provider | TalkifyTTS 适合作为可选云端提供方；不能作为唯一核心依赖 |
| AI 服务 | OpenAI-compatible Provider | 支持自定义 Endpoint/模型；仅开放受控高级参数 |

> TalkifyTTS 的可插拔 Endpoint / Model ID 思路可借鉴；其云端依赖、离线英语适配和模型许可需单独核验，不作为本产品唯一 TTS 基线。

## 8. 验收标准

### AC-01 首次闭环

用户选择任一内置词书并设定有效目标后，应用创建当日计划。用户完成计划新词与当日到期复习后，严格模式显示“今日完成”和文章入口；若当日无到期复习，完成计划新词即可解锁。

### AC-02 进度与恢复

对 N 个新词和 M 个复习词，用户完成部分反馈后退出并重新打开，新增、复习、已完成和剩余数量均保持正确。重复提交同一反馈不得增加完成数。

### AC-03 三档间隔复习

对同一初始状态分别提交不认识、模糊、认识，系统保存历史事件并安排未来复习，满足不认识不晚于模糊、模糊不晚于认识；当日已有效完成的复习词不重复计入待复习数。

### AC-04 解锁规则

严格模式下，只完成新词但未完成今日计划到期复习时，不得解锁新文章；补齐复习后解锁。宽松模式下，完成新词即可解锁且复习仍可继续。计划生成后新增到期词不影响已取得的解锁资格。

### AC-05 文章与阅读

已解锁用户选择文章类型后，AI 成功时保存标题、英文正文、中文全文翻译、命中词高亮和未覆盖词列表；文章长度符合最终长度档位容差。切换全文翻译默认展示不改写文章数据。AI 失败时今日完成状态仍保持且可重试。

### AC-06 离线查词和发音

离线词典命中时，不配置 AI 亦能显示基础词条；离线英语 TTS 可用时，单词和例句可播放。AI/端侧语音不可用时提供可行动提示且背词不受影响。

### AC-07 拍照翻译隐私

用户拍照或选图后，OCR 文本可编辑；未经用户确认不得上传图片或识别文本到第三方 AI。OCR/翻译失败时保留可复制原文；未主动保存时原图不会出现在历史或备份中。

### AC-08 AI 密钥隔离

创建、使用、导出、恢复和日志记录后，备份包、业务数据库、文章来源、日志和诊断中均不得存在 API Key 明文；恢复后要求用户重新填写密钥。

### AC-09 备份与迁移

旧设备生成一次性、未过期的配对凭据后，新设备在格式、版本、密码（如启用）、哈希、签名、资源关联和磁盘空间均通过时，才能替换恢复数据。篡改一个资源、使用错误/过期/已使用配对凭据、输入错误密码或缺失资源时，导入必须失败且导入前本机数据保持不变。

### AC-10 提醒与异常

启用提醒且当日未完成时，在设定时间收到本地提醒；权限拒绝或设备重启/时区改变后，设置页准确说明状态，并重新安排下一次可用提醒。

## 9. 版本规划

### P0（首版）

词书与学习计划、三档反馈与 FSRS 调度、每日完成与文章解锁、文章生成与双语阅读、离线查词、系统发音、本地提醒、AI 配置、基础拍照翻译、导出/配对认证/可选密码恢复、历史记录与基础统计。

### P1（增强）

Piper 端侧语音下载、TalkifyTTS/更多云端发音提供方、AI 音频离线缓存与可选备份、收藏与错词专项复习、文章小测、更多统计、文章重新生成与版本管理、无 GMS OCR 体验优化。

### P2（后续）

多端云同步、匿名/账号体系、词书导入、考试专项路径、AI 对话与口语跟读、专家模式 AI 请求配置、用户自有 WebDAV 备份。

## 10. 待进入技术设计前确认的事项

1. 初始词书的内容来源、授权范围、词条规模与更新机制。
2. FSRS 三档反馈与算法内部评分的最终映射参数。
3. 文章长度的“简短/标准/长篇”具体范围与可接受容差。
4. AI 文章“换一篇”的每日次数上限、成本提示与历史保留策略。
5. 旧设备配对在旧机不在线、设备遗失或仅有备份文件时的替代恢复策略；本 PRD 默认要求旧设备可参与首次新设备信任建立。
6. SQLCipher 是否默认启用，以及低端设备的性能验收指标。
7. 首发地区设备覆盖策略，尤其是无 GMS 设备的 OCR、系统 TTS 引擎检测与安装引导。
8. TalkifyTTS 的实际 Android 集成方式、云端供应商条款与可用于商业发行的语音模型清单。
