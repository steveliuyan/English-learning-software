# 学习记录与词书单词列表设计

- 日期：2026-09-30
- 对应规格：`docs/specs/01-vocabulary-learning-and-review.md` F1-07
- 决策记录：`docs/decisions/2026-09-30-learning-records.md`

## 一、目标

背完单词后能回头看：今天学了哪些词、以前每天学了哪些词、当前词书里有哪些词，并能从任意一行打开词卡详情。

来源是 2026-09-30 真机走查：词卡详情只在学习流程里提交「模糊 / 不认识」后出现，背完就再也看不到；阅读历史里点高亮词也打不开详情。用户明确：看详情的正确入口是学习记录与词书单词列表，而不是历史文章的点词。

## 二、非目标

- 搜索框、离线查词、AI 查词（第 2 块，另立规格）。
- 拍照翻译、扫码（第 3 块，另立规格）。
- 统计、收藏、错词本、连续天数（仍属阶段 4 F4-01 / F4-02）。
- 「重新学习」的真实功能（本次只隐藏无效按钮，见第六节）。
- 修改历史文章点词的行为（保持现有「离线词典入口」占位，交给第 2 块）。

## 三、入口与页面结构

- 首页「今日学习进度」卡片下方新增「学习记录」按钮，与「查看打卡与成就」并列。
- 打开后为全屏页面，左上角返回，进出方式与打卡页一致（`AppScreen` 的 overlay 标志 + 独立 ViewModel）。
- 页面顶部三个标签：

| 标签 | 内容 | 每行 |
|---|---|---|
| 今日已学 | 今日计划内已提交反馈的词，按提交时间先后 | 单词 · 首条释义 · 当时反馈 |
| 历史记录 | 全部已学词，按学习日分段，最新在前；段标题如「9月30日 · 2 词」 | 同上 |
| 全部单词 | 当前活动词书全部词，顺序同词书；顶部筛选「全部 / 未学 / 学习中 / 待复习」并带数量 | 单词 · 首条释义 · 当前状态 |

- 点任意一行打开词卡详情（`CardDetailScreen`）。详情为纯查看：不写任何学习事件，不影响今日完成度与解锁判定（沿用 AC1-11）。
- 反馈文案统一为「认识 / 模糊 / 不认识」，与学习页三档一致。

## 四、数据来源

不改表结构，不需要迁移。新增一个只读 DAO 与一个仓库接口 `LearningRecordRepository`，Room 实现走 `@Named("io")` dispatcher。

### 4.1 今日已学

- 查询今日计划 `planId` 下的 `learning_events`，按 `occurredAtEpochMillis` 升序。
- 同一计划同一词只取**第一次**提交（F1-03 已保证只能提交一次，这里是防御性去重）。

### 4.2 历史记录

- 范围：当前 profile 在**所有词书**下的事件（换过词书也能看到旧词书的学习记录）。
- `learning_events` JOIN `today_plans` ON `planId`，以计划的 `localDate` 作为学习日。
- 排序：`localDate` 降序，同日内 `occurredAtEpochMillis` 升序。
- 同一 `(planId, cardId)` 只取第一次提交。
- 以计划日期而非事件时间换算日期，保证同一学习日内改时区不会被拆成两天（与 F1-02 一致）。
- DAO 只返回平铺行；分组与计数在 ViewModel 的纯函数中完成，便于 JVM 测试。

### 4.3 全部单词与状态

- 词卡：`WordCardSource.cardIds(活动词书)` + `cards(...)`，顺序即词书顺序。
- 状态：读取该词书的 `card_review_states`，按下表判定；「现在」取 `ClockProvider`。

| 状态 | 规则 |
|---|---|
| 未学 | 无 `card_review_states` 行 |
| 待复习 | `nextReviewAtEpochMillis <= now` |
| 学习中 | `nextReviewAtEpochMillis > now` |

### 4.4 词卡找不到

- 学习事件只存 `cardId`。若词卡已不可解析（换词书、删词书、包损坏），该行仍保留：显示 `cardId` 最后一个 `:` 之后的部分作为单词，行置灰、不可点，并说明「这个词已不在当前词书中」。
- 学习历史不因词书变化而消失（AGENTS.md「切换词书不得删除旧记录」、F1-01「默认保留历史」）。

## 五、加载、缓存与错误

- 每个标签**首次选中时**才加载，加载中显示「正在读取…」。
- 结果缓存在 ViewModel；切换标签不重复读取；重新进入页面时刷新。
- 全部读取在 IO 线程。
- 读取失败：显示「学习记录暂时无法读取」与「重试」，不崩溃、不展示半份数据。
- 空状态只显示一句说明（如「今天还没有学习记录」），不留空表头或「暂无」占位（沿用 AC1-12 的精神）。今日尚未生成计划 → 今日已学为空；尚未选择活动词书 → 全部单词为空。
- 已知限制：导入册每次读取都会整册解析并校验配图。当前词书 10–100 词可忽略；上千词的词书可能需要一两秒，届时单独优化。

## 六、「重新学习」按钮

- 现状：`CardDetailScreen` 的 `onRelearn` 在任何调用方都没有传入，点击无反应。
- 改为可空回调：只有传入具体操作时才显示按钮。学习流程与学习记录里的详情页均不传，因此都不显示。
- 不做真实功能的原因：今日计划生成后不可改写（F1-02），学习事件只追加、V1 不提供撤销（F1-03）。任何「重新学习」都需要新的事件类型或练习模式，需另立规格。

## 七、测试

### 7.1 JVM

- 状态判定边界：无记录 → 未学；`next == now` → 待复习；`next == now + 1ms` → 学习中。
- 历史分组：学习日降序、同日提交先后；同一学习日改时区不拆分。
- 去重：同计划同词只保留第一次提交。
- 找不到的词：`ngsl-core-100:parent` → 显示 `parent`，不可点。
- ViewModel：按标签懒加载、切换不重读；失败后重试成功；筛选数量与列表行数一致。

### 7.2 设备（`adb shell am instrument`，每次运行前需用户授权）

- DAO / 仓库：内存数据库，不接触真实数据。
- 页面：三标签切换；空状态只有一句话；找不到的词置灰不可点；筛选数量正确；点行打开详情。
- 详情页：未传 `onRelearn` 时不显示「重新学习」（替换原「点击重新学习触发回调」测试）。
- 每次运行前后核对真实数据库三件套 MD5。

### 7.3 真机验收

- 今日已学：`possible · 模糊`、`parent · 模糊`。
- 历史记录：出现 9月29日与 9月30日两段。
- 全部单词：`ngsl-core-100` 的 3 个词状态正确。
- 打开学习记录前后数据库三件套 MD5 一致（只读）。
