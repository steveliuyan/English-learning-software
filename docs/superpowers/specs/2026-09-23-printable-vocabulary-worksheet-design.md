# 可打印单词表与默写纸设计

## 目标

为已学习单词提供一条完全离线的闭环：用户在学习工具中选择词条范围和默写设置，先查看与最终 PDF 一致的 A4 分页预览，再导出或通过系统分享/打印。

## 范围

首版提供以下能力：

- 学习工具入口，包含“导出单词表”和“生成默写纸”。
- 三份导出模板，版式对齐用户提供的参考样例：
  - **我的词表（`FULL_LIST`）**：双向并排的完整词表，每页 40 词（左半 1–20、右半 21–40，连续编号），直接打印背诵。
  - **我的词表 · 拼写测试（`SPELLING_TEST`）**：每页 20 词，左右两组镜像。左侧印单词与音标、释义留空；右侧单词留空、释义印出。
  - **我的词表 · 艾宾浩斯抗遗忘（`EBBINGHAUS_REVIEW`）**：每页 20 词，单组 `No./Word(含音标)/Meaning`，右侧 `Review` 列带 `D1 D2 D4 D7 D15 D30 D60 D90` 打卡空格。
- 默认范围为当前学习日计划中已经提交反馈的单词；范围可切换为当天全部计划词、当天已完成的新词、当天已完成的复习词和当天易错词。
- 两种可同时选择的默写方向：中文释义到英文、英文单词到中文释义。仅拼写测试模板消费方向；完整词表与艾宾浩斯模板都直接印出单词与释义，与方向无关。
- A4 练习页、可选英语四线三格、日期栏、页码和可选独立答案页。
- 生成前预览，预览使用与导出同一个分页和绘制模型；用户可逐页查看，并可返回修改设置。
- 将 PDF 仅保存至应用私有缓存或文件目录，以 FileProvider 的 `content://` URI 交给 Android 系统分享面板、外部查看器或打印服务。

首版不提供云端上传、AI 生成、真实词书之外的数据导入、老师批改、随机多套试卷、跨日期批量导出或 PDF 历史持久化。

## 用户流程

1. 用户从后续设置中心的“学习工具”进入；在正式设置中心尚未落地前，本功能可由今日计划页的“学习工具”次级入口访问。
2. 用户选择“导出单词表”或“生成默写纸”。
3. 系统读取当前学习日不可变计划、已保存的学习事件和本地词卡内容；只有成功提交反馈的词才属于“今天已学习”。
4. 用户选择导出模板、词条范围、（拼写测试模板下的）默写方向、是否使用四线三格和是否添加答案页。
5. 点击“预览默写纸”。系统先在本地写出 PDF，再把该 PDF 的每一页渲染成位图，逐页显示真实纸张画面；预览的图片来源与导出交给系统的是同一个文件，因此不存在“预览与导出不一致”。
6. 用户可返回设置重新选择模板或调整开关（已选内容不丢失），或在预览页点击“导出 PDF”。系统使用 Android Sharesheet；分享面板同时提供“分享/打印”目标与“用 PDF 阅读器打开”目标。

## 数据与领域边界

### 词条选择

新增纯领域用例 `BuildWorksheetContentUseCase`，依赖：

- `TodayPlanRepository`：读取当前 profile 的最新学习日计划；
- `LearningEventRepository.completedCardIds(planId)`：从 append-only 事件日志确定完成项；
- `WordCardSource.cards(cardIds)`：按计划顺序读取本地词卡。

用例必须以 `plan.dueCardIds + plan.newCardIds` 的稳定顺序取交集，去重后取卡片。因此：

- 未提交反馈的卡绝不导出为“今天已学习”；
- 计划外事件绝不混入；
- 同日计划的到期复习排在新词前；
- 词卡缺失时跳过该 ID，并在结果中返回缺失数量；
- 计划或存储不可读时失败，不生成空白的“成功”文件。

首版的“易错词”定义为：当前计划中最近一次反馈为 `Unknown` 或 `Fuzzy` 的完成词。为避免 N+1 查询，应为本次导出增加一条按 `planId` 查询事件反馈的仓储方法，而非逐词 `findCardState`。

### 文档模型

新增独立、Android 无关的 `WorksheetDocument`：包含纸张、标题、题目页、答案页和页码。`WorksheetItem` 只保存渲染所需的 `lemma`、`meaningZh`、`ipa`、`partOfSpeech`、例句及题号，不保存 API Key、AI Profile、完整学习事件或用户私人资料。

`WorksheetDirection` 为 `ZH_TO_EN` 和 `EN_TO_ZH`。`requiresDirection()` 只在 `SPELLING_TEST` 下为真：此时两个方向可以同时选择，生成顺序固定为中译英题目页、英译中题目页、答案页，每个方向各自从新的一页开始分块。`FULL_LIST` 与 `EBBINGHAUS_REVIEW` 不消费方向，`WorksheetDocumentBuilder` 只生成一个 `direction = null` 的分组，避免同一份词表被方向重复一遍。答案页按同一题号顺序列出英文、音标、词性和中文释义。

`WorksheetSettings` 必须是可序列化的 UI 值：模板、范围、方向集合、四线三格开关、答案页开关。默认值为“拼写测试模板 + 当前学习日已完成词 + 中译英 + 四线三格 + 答案页”。首版在界面重建期间保存在 `SavedStateHandle`，不写 Room；后续设置中心可以增加长期默认值。

### 设置与预览的状态机

`WorksheetUiState` 只保留一份 `settings`，设置页与预览页读写的是同一份：

- `settings` 在任何阶段都可以修改，因此“返回修改”不会把模板重置成默认值，也不会让开关失效。
- `preview()` 从设置页或预览页都可以调用，每次都按当前 `settings` 重新构建文档并重新分页；不存在“第二次预览沿用第一份结果”的情况。
- `dismissPreview()` 只把阶段退回设置页，保留 `source` 与 `settings`。
- 需要方向却未选任何方向时不进入预览页，只在设置页给出可读原因。
- PDF 渲染带代次号（generation）：过期渲染完成时丢弃并删除其产物，避免旧结果覆盖新结果。
- 分享只在用户显式点击“导出”时触发一次，界面消费后立即清空请求，重进预览页不会重复弹出分享面板。

分页与 PDF 写入被抽在端口后（`WorksheetPdfWriter`），PDF 写入在实现内部切到 IO 线程，因此
`WorksheetViewModel` 的状态机可以在 JVM 上用假实现确定性地测试。

### 分页与渲染

新增 `WorksheetPaginator` 作为纯 Kotlin 布局器：以 A4 宽高、统一边距和行高计算 `WorksheetPage`。测量和分页规则只在此处定义，预览与 PDF 渲染均消费该输出，禁止分别写两套分页逻辑。

- A4：595 × 842 pt；表格区左右各 42 pt、上下 66–800 pt；标题基线与右下 `Page-N`、右上 `Date：` 分列。
- 每页词数由模板决定，不做统一分页：`FULL_LIST` 每页 40 词（渲染时左右各 20 行），`SPELLING_TEST` 每页 20 词，`EBBINGHAUS_REVIEW` 每页 20 词。答案页每页 20 条。
- 渲染端把每栏容量固定为 20 行；**只绘制有数据的行**，不为凑满容量画空格子（空格子会被当成渲染缺陷）。行高由 `(表底 - 表顶) / (容量行数 + 表头行数)` 推导，因此满页恰好铺满、词条少时保持同一行高收尾，表头也不会被撑大；艾宾浩斯模板表头占两行，避免压到页脚。
- 四线三格只作用于拼写测试模板的留空单元格，三条实线与一条红色虚线均为自主绘制的通用书写辅助线，不复制任何第三方模板。
- 行不能跨页；当一个方向没有题目时不创建空白题目页；需要方向而未选择任何方向时，预览按钮禁用并显示“至少选择一种默写方向”。
- **墨色契约（`WorksheetInk`）**：单词近黑加粗（`#111111` / 8 pt）、音标淡灰小字（`#A3ABA8` / 6.6 pt）、释义中灰（`#333333` / 7.5 pt）。单词与音标必须**分行**绘制且明暗差足够明显，用户要求“一眼能区分”；该相对关系由 `WorksheetInkTest` 锁定，避免以后微调配色时把两者调成一样重。单词在上、音标在下，单元格文本块在行内垂直居中，避免多行单元格贴顶而与相邻列失去对齐。

版式元素对齐参考样例：外层页面装饰框为圆角青绿描边（半径 10 pt，与表格之间留有空隙、互不接触）；**表格本体一律直角**——表头底色（深青底白字）、交替行底色、单元格网格线与表格外框全部是直角矩形。混用直角与圆角会在四角产生「直角的填充边缘 + 圆角的轮廓弧线」，看起来像两个角叠在一起、填充色溢出弧线（用户实测反馈），因此表格内不得出现任何圆角。`WorksheetTemplateVisualTest` 用角点取样断言「外框必须闭合到左上角」来锁住这条约束。

每一张表都画完整外框与全格网格（含左右外边线），表头、数据行与艾宾浩斯的 `Review` 列读起来是一张连续的表；艾宾浩斯模板的 `No./Word/Meaning` 是跨两行的合并表头（列宽与数据行共用 `REVIEW_TEXT_COLUMNS`），`D1…D90` 只占表头第二行。

Android 实现使用框架 `android.graphics.pdf.PdfDocument` 和 `Canvas` 自主绘制，不新增第三方 PDF SDK。预览使用 `PdfRenderer` 将已生成的私有 PDF 渲染为页位图，Compose `LazyColumn` 显示真实纸张页面图像。

## Android 文件、安全与分享

- PDF 生成到 `cacheDir/worksheets/`；以安全的 `worksheet-<timestamp>.pdf` 命名。
- 通过 `androidx.core.content.FileProvider` 输出临时 `content://` URI。Manifest provider 必须 `exported=false`、`grantUriPermissions=true`，并仅暴露 `cache-path` 的 `worksheets/` 子目录。authority 在代码中由 `context.packageName + ".worksheetfiles"` 推导，与 Manifest 的 `${applicationId}.worksheetfiles` 始终一致，换构建变体也不会失配。
- 外发使用 `Intent.ACTION_SEND`、`type = "application/pdf"`、`Intent.EXTRA_STREAM` 与 `FLAG_GRANT_READ_URI_PERMISSION`；同时通过 `EXTRA_INITIAL_INTENTS` 附带一个 `ACTION_VIEW` 目标，让用户能直接用 PDF 阅读器打开导出结果。只读权限标志与 `clipData` 在 chooser 上再声明一次，避免部分 ROM 的 chooser 不透传内层 Intent 的权限。不使用文件路径 URI，不申请存储权限，不把 PDF 写入公共目录。
- 分享面板无法拉起时（设备上没有可处理 PDF 的应用）给出可读中文提示，不静默失败也不崩溃。
- 预览或导出失败时删除不完整文件，页面显示不泄露路径、词表内容或底层异常的中文错误提示。
- 不增加网络权限；所有筛选、分页、PDF、预览和分享均在设备本地完成。

## UI 与导航

新增三张 Compose 页面：

1. `LearningToolsScreen`：浅薄荷背景、白色卡片、工具宫格；首版两个可点击工具，后续“错词再练”显示为未开放，不伪装成已实现功能。
2. `WorksheetSettingsScreen`：模板单选、范围选择、双向复选（仅拼写测试模板可见）、四线三格开关、答案页开关、词数摘要和“预览默写纸”。
3. `WorksheetPreviewScreen`：逐页显示由真实 PDF 渲染出的纸张图像、页数与模板标签、重新设置和“导出 PDF”。

所有交互提供稳定 `testTag` 和 `contentDescription`。颜色沿用现有 Mint token；强调色只用于主操作和选择态。预览页不得使用 WebView。

在现有 `AppScreen` 的 Ready 分支增加局部导航状态：今天计划 → 学习工具 → 设置 → 预览；返回按相反顺序工作，不影响正在进行的学习会话。未来正式三栏导航/设置中心落地时，只迁移入口，不迁移领域、分页或 PDF 实现。

## 验收标准

- 当前学习日已完成词导出结果只包含完成计划项，且顺序为复习后新词。
- 三份模板的分页行为分别可验证：`FULL_LIST` 为 `40/页`，`SPELLING_TEST` 与 `EBBINGHAUS_REVIEW` 为 `20/页`；每页渲染网格固定 20 行/栏。
- 只有拼写测试模板把词条拆成中译英、英译中两组；完整词表与艾宾浩斯模板只生成一组，选择两个方向也不会把词表重复两遍。
- 拼写测试左右镜像正确：左栏有单词与音标、释义空白；右栏单词空白、释义印出。
- 中译英、英译中可单选或同时选择；两种题目页与答案页的词序和题号一致。
- 预览页的页数、题号和分页与最终 PDF 完全一致。
- 四线三格开关只改变拼写测试模板的留空单元格线条，不改变答案页。
- 无完成词、需要方向却未选方向、计划/存储不可读和 PDF 渲染失败均有明确本地错误态，不产生或分享无效文件。
- 分享 Intent 只携带 `content://` PDF URI 且授予只读临时权限；不存在公共存储写入、网络请求或 API Key 泄漏。
- 在 Android 13 真机上生成、预览并唤起系统分享面板；真机证据至少包含设置页、预览页和系统分享面板。

## 开源参考与许可边界

- `leichongxiang/HengshuiFont-English-Generator`：根 LICENSE 为 Apache-2.0；首版仍选择自主实现。如以后逐文件复制其代码或资产，必须先复核该文件及依赖的许可证，并保留 Apache-2.0 许可证、版权归属、NOTICE（如存在）和修改说明。
