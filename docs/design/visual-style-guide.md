## 1. 设计方向

产品视觉应传达：清爽、轻盈、可靠、适合长期学习。

核心原则：

1. **明亮但不刺眼**：使用浅色背景和苹果青绿作为品牌识别，不使用深森林绿作为大面积主色。
2. **柔和但不含糊**：通过浅色卡片、细边框、适度圆角和明确的选中状态建立层次。
3. **内容优先**：学习目标、词书名称、进度和行动按钮必须比装饰更醒目。
4. **一致过渡**：系统启动首帧、品牌启动页、应用内 Loading 和桌面图标必须属于同一视觉家族。
5. **本地优先的可信感**：不使用会让界面显得像广告、游戏或营销落地页的过度动效和装饰。

## 2. 色彩令牌

### 2.1 品牌渐变

品牌渐变由左上至右下或按页面空间自然展开，固定使用以下三段：

| 令牌 | 色值 | 用途 |
| --- | --- | --- |
| `AppleMintStart` | `#A8F3C8` | 最浅起始色、系统浅色启动首帧参考色、图标渐变起点 |
| `AppleMintMiddle` | `#5DDFB4` | 主品牌青绿色、渐变中段 |
| `AppleMintEnd` | `#35B9B5` | 青蓝收束色、渐变终点、图标深色细节 |

品牌渐变不得随页面临时改色。若需要强调状态，优先使用透明度、边框和布局层级，而不是新增近似绿色。

### 2.2 应用内基础色

| 令牌 | 当前参考色 | 用途 |
| --- | --- | --- |
| `MintBackground` | `#F1FBF5` | 应用页面大面积背景 |
| `MintSurface` | `#EFFFFFFF` | 半透明白色卡片表面；仅用于轻微透出背景的场景 |
| `MintSurfaceSolid` | `#FFFFFF` | 需要实底的卡片与弹层（不透明，避免文字压在背景纹理上） |
| `MintTint` | `#DDF7E8` | 选中卡片、提示卡、浅青强调区域 |
| `MintTint2` | `#DCEAE1` | 中性浅底容器（图标容器、次级标签底） |
| `MintTint3` | `#CDEDD9` | 稍深浅底（进度轨道、图表网格） |
| `MintPrimary` | `#2EC99C` | 主操作、选中态、滑条和单色品牌强调 |
| `MintPrimaryDark` | `#188F76` | 标题、重要文字、深色品牌文字 |
| `MintOutline` | `#ADE7D2` | 柔和边框、分组轮廓 |
| `MintOutlineSoft` | `#E4EFE9` | 分隔线（唯一允许的分隔用色；禁止用 `spacedBy` 造不可见间距） |
| `MintTextStrong` | `#1C1C1E` | 正文与标题主文字 |
| `MintTextMuted` | `#4E756A` | 辅助文字、说明文字、次级信息 |
| `MintTextFaint` | `#7A9088` | 时间戳、脚注一类可省略信息；不得承载唯一操作信息 |
| `OnMintForeground` | `#174C44` | **浅薄荷底与品牌渐变上的前景文字/图标专用色**（实测对比 ≈4.6:1） |
| `OnBrandDeep` | `#04241C` | 渐变上需要更深字重时的唯一替代 |
| `MintError` | `#B30000` | 错误文字与破坏性操作文字（全站唯一） |
| `MintErrorFill` | `#FF3B30` | 破坏性操作的填充/图标底（全站唯一） |
| `MintSuccess` | `#1B5E20` | 成功回显文字 |
| `AppleMintLight` | `#D9FFF0` | 极浅品牌高光、装饰性背景 |

文字必须保证足够对比度。浅色背景上不得使用低对比度的浅青文字；辅助文字只能用于非关键说明，不能承载唯一操作信息。

**硬规则（F5-03 移交，任何批次不得回潮）**：`MintBackground`、`MintTint` 系与品牌渐变 `#A8F3C8 → #5DDFB4 → #35B9B5`
之上**禁止白色前景**（`#FFFFFF` 与近白一律不可），前景文字与实底容器上的图标一律走 `OnMintForeground #174C44`。
对比度必须由 WCAG 相对亮度函数计算得出（≥4.5:1），不得凭肉眼或经验宣称达标。

**与代码现状的差值（批 1 须校准，勿当已就位）**：`ui/theme/AppPalette.kt` 已存在且全站 154 处引用，
但其中性色取值偏 iOS 灰，与本表不一致：`Background #F5F5F7 → #F1FBF5`、`TextSecondary #6E6E73 → #4E756A`、
`Separator #E5E5EA → #E4EFE9`、`GlassFill #CCFFFFFF → #EFFFFFFF`；`DomainColors` 七域取值与本规范 §2.3 **逐值一致**，
`OnMintPrimary #174C44` 与 `ErrorText #B30000` 保持原样。缺的令牌（`tint2/tint3/outlineSoft/onBrand/errorFill`）
随装配点一并补齐。

### 2.3 功能域强调色（UI 重设计轮新增）

七个功能域各有一对颜色：`base` 用于实底容器与图形起点，`deep` 用于浅底上的文字与字形。
域色只表达"这是哪个功能区"，不表达状态（状态仍由 `MintError` / `MintSuccess` 与文字承担）。

| 域 | 浅色 `deep` / `base` | 深色（deep 与 base 合一） |
| --- | --- | --- |
| AI | `#188F76` / `#2EC99C` | `#35E0AC` |
| 学习 | `#075EB4` / `#0A84FF` | `#5AC0FF` |
| 复习 | `#AB5700` / `#FF9F0A` | `#FFB340` |
| 词库 | `#8E34B8` / `#BF5AF2` | `#DA8CFF` |
| 阅读 | `#C81E46` / `#FF375F` | `#FF7A93` |
| 危险 | `#B30000` / `#FF3B30` | `#FF6B61` |
| 设置 | `#48484A` / `#8E8E93` | `#B0B0B5` |

- 两种合法呈现：域色容器（实底或渐变）+ 白色字形，或域色浅底 `tint` + 域色 `deep` 字形与文字。
  **图形本身要按非文本对比 ≥3:1 当场算**（WCAG 1.4.11），不得宣称"图标不参与对比度判定"。
  实测：白字形在浅色 `deep` 实底上 4.02:1 ~ 9.12:1 全部合格；但**直接以浅色 `base` 作容器底时不合格**——
  AI `#2EC99C` 上 2.11:1、复习 `#FF9F0A` 上 2.06:1。故渐变容器的高光端一律取 `deep` 混 35% `base`（不是 `base` 本体），
  七域白字形实测 3.17:1 ~ 6.26:1（最差 AI）；深色下容器用同组域色配 `#06231A` 字形，实测 5.96:1 ~ 9.82:1（最差危险）。
- 容器上的任何**文字**仍受 §2.2 硬规则约束。
- **同口径补充（2026-10-18 裁决）**：`text-3 #7A9088` 不作任何正文或标签前景（压 `surface`/`bg`/`tint` 实测
  3.40/3.22/3.00，只留 ≥24sp 大数字/装饰与纯图标描边）；`text-2 #4E756A` 只许压 `surface`/`bg`/`tint`
  （5.15/4.87/4.55），禁压 `tint-2`/`tint-3`（4.15/4.10），其上正文一律 `text-1`；品牌渐变上的文字统一取
  `on-brand #04241C`（`on-mint` 压末端仅 4.07），§2.2 表内 `OnMintForeground`「≈4.6:1」与 `OnBrandDeep`
  「唯一替代」两行旧措辞以此为准、随批 1 token 校准改写。裁决全文见
  `docs/decisions/2026-10-18-ui-redesign-contrast-and-icon-layer-rulings.md`。
- 禁止在页面里现场调色（裸 `Color(0xFF…)`）。现存待清残留：`TodayPlanScreen.kt:160-161` 的 `#68BDA6`/`#C7A47D`、
  `:247` 的 `#795B36`、`AppScreen.kt:2223`/`:2336`。

### 2.4 深色模式

深色模式只调整系统首帧、页面背景、表面和文字对比，不改变苹果青绿品牌渐变的识别关系：

- 系统启动首帧：纯黑背景；
- 系统启动页不显示中心品牌图标；
- 品牌渐变页仍使用同一组 `#A8F3C8 → #5DDFB4 → #35B9B5`；
- 深色页面使用深色表面与浅色文字，禁止直接把浅色页面反相后产生刺眼的高亮块；
- 主操作仍保持青绿色识别，但应通过文字/边框对比确保可读性。

深色取值见 §2.5，域色取值见 §2.3。**深色此前没有落点**：全仓库既没有 `isSystemInDarkTheme()` 调用，
也没有主题设置项。批 1 建立唯一装配点（`ui/theme/` 下的 `MaterialTheme(...)`）后，
由「跟随系统 / 浅色 / 深色」三态设置（新增项，用 `Context.getSharedPreferences` 持久化，
不进 Room、不进备份包）与系统设置共同决定；页面代码一律不写 `if (dark)` 现场调色。

### 2.5 深色令牌（UI 重设计轮新增）

深色不是"浅底反相"，而是一整套取值；所有域色在深色下 `deep = base`，避免暗底深字。

| 令牌 | 浅色 | 深色 |
| --- | --- | --- |
| 背景 | `#F1FBF5` | `#0E1512` |
| 实底表面 | `#FFFFFF` | `#17201C` |
| 玻璃表面 | `#EFFFFFFF` | `#E617201C`（90% 不透明，深色下不再叠更低透明度） |
| 浅底容器 | `#DDF7E8` / `#DCEAE1` / `#CDEDD9` | `#1C2C26` / `#22322B` / `#27392F` |
| 边框 | `#ADE7D2` / `#E4EFE9` | `#2E4238` / `#233029` |
| 文字 | `#1C1C1E` / `#4E756A` / `#7A9088` | `#E9F2EC` / `#9FB3AA` / `#7F938A` |
| 渐变/浅底上的前景 | `#174C44` | `#DFF6EC` |
| 错误 / 填充 | `#B30000` / `#FF3B30` | `#FF8177` / `#FF6B61` |
| 成功 | `#1B5E20` | `#6BD98A` |

品牌渐变在深浅两套下保持同三段，识别关系不变。

## 3. 排版规范

### 3.1 层级

优先使用 Material 3 typography，并保持以下语义层级。UI 重设计轮把六档钉值固定为 `AppType` 语义名，
新代码只写语义名，M3 角色名留给既有调用点自然淘汰：

| 语义档 | 钉值 | 推荐 M3 角色 | 使用方式 | 相对现状 |
| --- | --- | --- | --- | --- |
| `Display` | `34.sp` Bold，字距 `0.4` | `displaySmall` | 数字锚点、今日核心数 | 36→34 |
| `Headline` | `24.sp` Bold | `headlineSmall` | 页面顶部唯一主标题，可用 `MintPrimaryDark` | 同值 |
| `Title` | `17.sp` SemiBold | `titleMedium` | 词书、每日目标等区块标题 | 16→17 |
| `Body` | `15.sp` Regular | `bodyMedium` | 说明、引导和主要内容 | 14→15 |
| `Footnote` | `13.sp` Regular | `bodySmall` | 等级、来源、补充说明 | 12→13 |
| `Label` | `12.sp` Medium，字距 `0.3` | `labelMedium` | “已选”、分类、短状态 | 同值 |

现状没有 `MaterialTheme(...)` 装配点，206 处 `MaterialTheme.typography.*` 直接吃 M3 默认值；
建立装配点（`ui/theme/`）是本轮批 1 的第一件事，装配点未建立前不得在页面里散写 `fontSize`。

### 3.2 文案与布局

- 页面顶部只保留一个明确主标题；不要堆叠多个同级大标题。
- 主标题下可放一行简短副标题，说明页面价值或下一步行动。
- 核心数字必须有单位或语义说明，例如“词”，不能只显示孤立数字。
- 关键操作使用动词，例如“保存并开始学习”，避免只写“确定”。
- 中文界面优先使用自然、短句式文案；不要把实现术语直接暴露给用户。
- 需要解释词书来源时，明确写“应用内学习分组，不是官方考试大纲”，不得暗示与中国官方考试大纲等同。

## 4. 间距、圆角与尺寸

以下值为默认基线；新页面只有在内容密度或无障碍要求确实需要时才可调整：

| 项目 | 基线 |
| --- | --- |
| 页面水平边距 | `20.dp` |
| 页面垂直内边距 | `24.dp` |
| 页面区块间距 | `24.dp`（段间；原 `14.dp` 降为卡内值） |
| 卡片内部边距 | `14.dp` |
| 间距档位 | 只允许 `4 / 8 / 12 / 14 / 16 / 18 / 20 / 24` 八档，禁止其它值 |
| 圆角：主视觉卡 / Hero | `24.dp` |
| 圆角：普通卡片 | `18.dp` |
| 圆角：按钮 | `14.dp` |
| 圆角：图标容器 | `12.dp` |
| 圆角：胶囊（短标签、状态徽章、喇叭药片） | `999.dp` |
| 主按钮高度 | `54.dp` |
| **触控目标下限** | **`48.dp`**（用 `heightIn(min = 48.dp)` 或 `defaultMinSize`，禁止靠 padding 凑数） |
| 词书卡片最小高度 | `72.dp` |
| 品牌页中心图标 | `180.dp` |
| 应用内 Loading 图标 | `48.dp` |

圆角表达柔和和亲和力，但不能让所有元素都变成胶囊形。胶囊形只用于短标签、状态徽章或明确的连续控件。

**幽灵间距禁令**：不得用 `Arrangement.spacedBy` 在没有可见内容的地方造"看不见的分隔"。
需要分隔时用真实可见的 `MintOutlineSoft` 线或明确的一档间距；否则在大字号下会表现为莫名其妙的空白。

## 5. 卡片与层次

### 5.1 卡片

- 卡片优先使用浅色表面，不使用厚重黑色阴影。
- 默认使用 `1.dp` 柔和边框配合圆角；选中卡片使用品牌色边框。
- 选中状态至少同时体现两种差异：背景/边框、单选控件、状态标签、文字或轻微动效。
- 卡片不得只依赖颜色表达选中状态，必须保留可读的文字或控件状态。
- 卡片内容按“标题 → 辅助信息 → 状态/动作”排列，避免信息四散。

### 5.2 高斯模糊与材质效果

高斯模糊不是默认装饰，而是有限使用的材质语言：

- 仅可用于品牌启动页、顶部浮层、底部浮层、弹层背景或明确需要与背景分离的半透明容器。
- 模糊应服务于层次和可读性，不能用于正文卡片来制造噪声。
- 模糊面板必须同时有半透明填充和足够对比度；不能只靠模糊承载文字。
- Android 版本或设备不支持实时模糊时，必须有静态半透明色的降级方案，不能出现空白或透明穿透导致文字不可读。
- 不在列表中的每张卡片重复使用大半径模糊，避免性能问题和视觉过度装饰。
- 当前 F1-01 页面以浅色卡片、透明度和边框建立层次；后续若加入高斯模糊，必须保持这种轻量原则。

### 5.3 说明图插画

词卡详情页的说明图是**内容性插画的唯一例外**（界面空态插画另立 §5.4，两类不可混用），
不与青绿令牌体系冲突，但必须遵守：

- **风格**：扁平卡通、柔和圆角、粗而平滑的轮廓线，单场景单一主体、居中并留出充足留白，儿童绘本级清晰度。
- **配色**：薄荷绿、青绿、暖珊瑚、柔黄、天蓝，辅以白 / 奶油 / 棕。**禁止出现洋红与紫色**（背景键控的判定色，残留即视作缺陷）；正文、卡片与品牌元素仍严格使用 §2 令牌，插画配色不得外溢。
- **背景**：透明底。插画直接「浮」在 `MintSurface` 卡片上，不加白色底块、不加描边框、不加投影、不加棋盘格。
- **尺寸**：卡片内 `160.dp`，`ContentScale.Fit`，不裁切。
- **资源**：`res/drawable-nodpi/illus_<lemma>.webp`，512×512 无损 WebP（位图不随密度缩放，不设多密度目录）。
- **无资源即隐藏**：不出现空标题、不显示「暂无」、不使用通用占位图（AC1-12）。
- **禁止**：在插画内绘制文字、字母、数字或水印；使用照片写实、3D 渲染，或与扁平体系冲突的质感。

生成、后处理与入库流程见 `docs/design/card-illustration-prompts.md`。

### 5.4 界面插画（空态与首启 · UI 重设计轮新增）

与 §5.3 的内容性说明图是**两类资产**，不可混用：§5.3 服务"看懂一个词"，本节服务"空页面不刺眼"。

- **数量硬上限 5 张**，逐张钉落点（首启未选词书 / 收藏为空 / 生词本为空 / 错词本为空 / 阅读历史为空）；
  新增第 6 张属范围变化，先改 `docs/decisions/2026-10-17-ui-redesign-illustrations.md` 与本节。
- **形式**：原创矢量，以 `ImageVector` 路径数据内嵌在 `ui/components/AppIllustrations.kt`，
  不放位图资源、不引入素材库或动画依赖。
- **配色**：只用 §2 令牌与 §2.3 域色（`tint` 系 + 域色 `base`/`deep`），线条重量与图标一致（2px 视觉重量）。
- **装饰性**：`contentDescription = null`。状态语义必须由标题 + 一句说明 + 一个动作承担，
  不得把唯一信息画进图形里让读屏软件读不出来。
- **静态**：本轮不做动效。打卡页"华丽动效"是视觉定稿后的独立批次，届时须单独处理
  减少动态效果与 TalkBack 朗读口径。
- 「AI 学」页表情（`ui/mascot/`，台账 `app-authored-ai-mascot`）为既有资产，不占本节的 5 张名额。
- 许可结论登记于 `docs/third-party-notices.md` 的 `app-authored-ui-illustrations`。

## 6. 交互与动效

- 选中卡片动效：短时、柔和，建议约 `180ms`，使用平滑缓动。
- 动效只强化状态变化，不阻塞用户操作，不延迟页面可用时间。
- 滑条支持连续拖动并实时显示 `1..50` 的整数目标；不要依赖难以命中的离散刻度。
- 动效期间内容位置不能明显跳动；滑块拇指和数字显示应保持稳定。
- 保存成功应提供清楚的文字回显；不能只依赖 Toast 或颜色变化。
- Loading、空状态和错误状态都必须有明确内容，不得只显示旋转指示器。
- 尊重系统减少动态效果设置；减少动效时仍保留状态和层次信息。

## 7. 启动页与品牌资产

启动流程固定为三段：

1. **系统首帧**：浅色模式纯白、深色模式纯黑；使用透明占位资源，不显示中间居中图标。
2. **品牌启动页**：苹果青绿三段渐变，中心使用同款语言气泡/叶片标识，尺寸 `180.dp`，正中心对齐。
3. **主页面**：进入应用页面后继续使用同一组品牌色和轻量卡片语言。

补充约束：

- 桌面图标可以使用完整自适应图标；启动页中心图标使用简化的同款标识，不把完整方形桌面图标套在启动页中。
- MIUI 等 OEM 可能在系统极早阶段显示自己的小型应用标识；这属于系统启动层，不应通过修改应用内品牌页来补偿。
- 不得在启动页增加 ActionBar、标题或额外文案。
- 启动页不能出现深森林绿大面积背景、紫色、蓝色或与主页面割裂的旧主题。

## 8. 无障碍与可用性

- 可点击卡片、单选按钮、滑条和主按钮必须有清晰的语义描述。
- 触控区域应足够大，不能为了追求紧凑而缩小核心操作。
- 颜色不是唯一信息来源；选中、错误、成功必须有文字、图标、边框或控件状态辅助。
- 核心文字不得放在过度透明、模糊或低对比度背景上。
- 横向空间不足时允许换行或滚动，不得裁切词书名称和目标数字。

## 9. 禁止事项

以下做法需要视为视觉回归，除非先更新本规范并获得产品确认：

- 恢复紫色旧主题或使用深森林绿作为主背景；
- 随意替换品牌渐变色值；
- 将启动页中心图标恢复为完整桌面图标或任意放大到遮挡内容；
- 在系统白/黑首帧增加中心图标；
- 使用负 padding、负布局偏移或其他会造成 Compose 运行时崩溃的视觉技巧；
- 大面积重阴影、重模糊、玻璃拟态堆叠或营销式装饰；
- 仅通过颜色表达选中/错误/成功；
- 新页面自行引入未经定义的字体、颜色、圆角体系或间距体系；
- 将应用内学习分组描述为中国官方考试大纲或官方词表；
- 在未进行真机检查前宣称视觉一致；
- （UI 重设计轮新增）在浅薄荷底、`MintTint` 系或品牌渐变上使用白色或近白前景；
- （UI 重设计轮新增）在页面里写裸 `Color(0xFF…)`、裸 `fontSize` 或未经本文定义的圆角/间距——一律走令牌；
- （UI 重设计轮新增）用 emoji、字母缩写或数字当图标（「AI」「♪」「⏰」等含字徽标必须换成 §12 的矢量字形）；
- （UI 重设计轮新增）用不可见的 `spacedBy` 间距冒充分隔；
- （UI 重设计轮新增）破坏性操作使用危险域色以外的颜色，或与只读操作共用同一行形态；
- （UI 重设计轮新增）同一语义在多个页面各写一份组件实现（页头、词行、未配置卡、确认框、错误行等，见 §13）。

## 10. 新页面验收清单

提交新的 UI 功能前，至少检查：

- [ ] 背景、卡片、主操作遵循苹果青绿令牌；
- [ ] 没有引入紫色、深森林绿或未定义的品牌主色；
- [ ] 页面标题、区块标题、正文和辅助文字层级清楚；
- [ ] 页面边距、卡片圆角、主按钮尺寸符合基线；
- [ ] 选中、成功、错误和 Loading 状态不只依赖颜色；
- [ ] 高斯模糊/半透明材质有明确用途，并有无模糊降级方案；
- [ ] 动效短、可中断、不造成布局跳动，并尊重减少动态效果；
- [ ] TalkBack/语义描述覆盖核心操作；
- [ ] 说明图遵循 §5.3（透明底、无文字与水印、无洋红/紫色、卡片内 `160.dp`）；
- [ ] 空态插画在 §5.4 的 5 张名额内，且 `contentDescription = null`、语义由文字与动作承担；
- [ ] 图标全部来自 §12 的统一字形族，无 emoji、无含字徽标；
- [ ] 页头、词行、确认框、错误行等使用 §13 的共享组件，未新增第 N 份私有实现；
- [ ] 每一屏只承担自己的职责，页面里不出现别屏的数字或状态（逐屏口径见 `2026-10-17-content-placement-audit.md` §5）；
- [ ] 所有可点控件 ≥ `48.dp`，且在 `fontScale 2.0` 下不裁字、头部不被挤压；
- [ ] 浅色与深色模式均检查；
- [ ] 真机冷启动和页面截图与本规范一致；
- [ ] 如需偏离本规范，先更新本文档并说明原因。

## 11. 维护规则

本文档是视觉基线，不是一次性设计说明。任何新增颜色、字体、材质、启动流程或全局间距，都必须先在本文档中定义，再进入代码。代码中的视觉常量应尽量集中为主题令牌或专用组件，避免在页面中散落新的魔法值。

UI 重设计轮（2026-10-17）的图标体系与共享组件口径见 §12、§13；同一轮的六条信息架构裁决见
`docs/decisions/2026-10-17-ui-redesign-information-architecture.md`，实施规格见
`docs/superpowers/specs/2026-10-17-ui-redesign-design.md`。本文与规格冲突时以本文为准并须当场修订其一。

## 12. 图标体系（UI 重设计轮新增）

- **唯一字形族**：以 Material Symbols（Google，Apache-2.0）的 24dp 网格、2px 视觉重量、圆头描边、
  无填充优先为**度量基准**（不复制其路径数据）。图标矢量路径逐枚自行绘制，内嵌为 `ImageVector` 常量，
  集中放在 `ui/components/AppIcons.kt`；许可登记见 `docs/third-party-notices.md` 的 `app-authored-ui-icons`
  与 `material-symbols-icon-paths`（后者仅作基准说明）。选型过程见
  `docs/decisions/2026-10-18-ui-redesign-icon-duotone.md`。
- **呈现已定（B 案 · 双色层次）**：每枚图标两层结构——描边骨架 + 内部半透明填充层。
  入口层（≥40dp 容器）用域色渐变容器 + 白色两层字形；行内层（30dp 容器 / 17dp 图形）**退化为单层描边**，
  浅底 `tint` + 域色 `deep`，填充层不显示。**"高级感"只存在于 ≥40dp 容器**，行内不许出现实心图形或渐变块。
- **两层口径修订与文字同口径（2026-10-18 裁决）**：上一条「每枚图标两层结构」限定为**除豁免表内 5 枚外每枚两层**——
  `Back`/`ChevronRight`/`ChevronDown`/`Close`/`Check` 只有描边骨架、不建填充层，且不得进入 ≥40dp 入口容器；
  图标旁的文字同受 §2.3 补充口径约束（`text-3` 不作正文前景）。清单与裁决见
  `docs/decisions/2026-10-18-ui-redesign-contrast-and-icon-layer-rulings.md`。
- **禁止混用**：emoji、字母/数字缩写徽标、各处自绘异形图标、第三方品牌 logo（Google 明示该图标集不含第三方标志）。
  现状待清的含字徽标：「AI」「♪」「⏰」与打卡页头部两条裸文字链（后者按裁决③移出）。
- **容器口径**：容器圆角 `12.dp`（入口块可 `14.dp`），尺寸走 §4 档位；
  渐变亮端取 `deep` 混 35% `base` + `inset 0 0 0 1px rgba(255,255,255,.26)` 内高光，禁止直接用浅色 `base` 作白字形底。
- **对比度口径**：图形本身按 ≥3:1 当场计算（非文字，WCAG 1.4.11），容器上的任何文字另受 §2.2 硬规则约束。
  实测取值见 §2.3。
- **可访问名**：图标按钮必须有真实语义 `contentDescription`；纯装饰图形为 `null`。禁止把 `testTag` 当描述用（F5-03 已有契约测试拦截）。

## 13. 共享组件与每屏职责（UI 重设计轮新增）

**同一语义只允许一个组件**。下列组件的份数是实测现状（写进规范是为了让它可核验）：

| 组件 | 现状份数 | 目标 |
| --- | --- | --- |
| 页头 + 返回 | 14 个页头 / 6 种返回写法 | `AppScreenHeader` 一个 |
| 词行（lemma + 释义 + 状态/时间 + 动作） | 7 份私有实现、0 复用 | `WordRow` 一个 |
| AI 未配置提示 | 4 屏 12 行，4 处无出口 | `NotConfiguredCard`，必须带「去配置 ›」 |
| 出站确认对话框 | 5 份 | `OutboundConfirmDialog` 一个 |
| 破坏性确认 | 4 份 AlertDialog + 1 份行内、4 种措辞 | `ConfirmDestructiveDialog` 一个 |
| 错误 / 回执行 | 11 份实现 | `InlineNotice` 一个 |
| 喇叭与播控 | 两套同构几何 | `SpeakerButton` + 播控组一个 |

每屏只承担一个职责：今日计划只回答"今天做什么"，打卡页只回答"坚持得怎样"，
学习记录只回答"逐条发生了什么"，设置页只回答"要改哪条配置"。同一数字（今日新增/复习）
全站只在一处权威呈现，其余页面不复述。逐屏口径见 `2026-10-17-content-placement-audit.md` §5。

列表屏须为加载预留骨架高度，避免"卡一下然后内容突然蹦出来"；入口迁移必须先建新入口再摘旧入口。
