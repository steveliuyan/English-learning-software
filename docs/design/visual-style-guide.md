# English Learning 视觉设计规范

> 状态：项目级强制规范
>
> 适用范围：所有 Android 页面、组件、弹层、空状态、错误状态、启动页和应用图标。后续开发、重构和视觉验收均以本规范为基准。
>
> 当前基准：苹果青绿（Apple Mint）主题，已在 F1-01 词书设置页面和真机启动流程中验证。

## 1. 设计方向

产品视觉应传达：清爽、轻盈、可靠、适合长期学习。

核心原则：

1. **明亮但不刺眼**：使用浅色背景和苹果青绿作为品牌识别，不使用深森林绿作为大面积主色。
2. **柔和但不含糊**：通过浅色卡片、细边框、适度圆角和明确的选中状态建立层次。
3. **内容优先**：学习目标、词书名称、进度和行动按钮必须比装饰更醒目。
4. **一致过渡**：系统启动首帧、品牌启动页、应用内 Loading 和桌面图标必须属于同一视觉家族。
5. **本地优先的可信感**：不使用会让界面显得像广告、游戏或营销落地页的过度动效和装饰。

## 2. 色彩令牌

### 2.1 品牌渐变

品牌渐变由左上至右下或按页面空间自然展开，固定使用以下三段：

| 令牌 | 色值 | 用途 |
| --- | --- | --- |
| `AppleMintStart` | `#A8F3C8` | 最浅起始色、系统浅色启动首帧参考色、图标渐变起点 |
| `AppleMintMiddle` | `#5DDFB4` | 主品牌青绿色、渐变中段 |
| `AppleMintEnd` | `#35B9B5` | 青蓝收束色、渐变终点、图标深色细节 |

品牌渐变不得随页面临时改色。若需要强调状态，优先使用透明度、边框和布局层级，而不是新增近似绿色。

### 2.2 应用内基础色

| 令牌 | 当前参考色 | 用途 |
| --- | --- | --- |
| `MintBackground` | `#F1FBF5` | 应用页面大面积背景 |
| `MintSurface` | `#EFFFFFFF` | 半透明白色卡片表面；仅用于轻微透出背景的场景 |
| `MintTint` | `#DDF7E8` | 选中卡片、提示卡、浅青强调区域 |
| `MintPrimary` | `#2EC99C` | 主操作、选中态、滑条和单色品牌强调 |
| `MintPrimaryDark` | `#188F76` | 标题、重要文字、深色品牌文字 |
| `MintOutline` | `#ADE7D2` | 柔和边框、分组轮廓 |
| `MintTextMuted` | `#4E756A` | 辅助文字、说明文字、次级信息 |
| `AppleMintLight` | `#D9FFF0` | 极浅品牌高光、装饰性背景 |

文字必须保证足够对比度。浅色背景上不得使用低对比度的浅青文字；辅助文字只能用于非关键说明，不能承载唯一操作信息。

### 2.3 深色模式

深色模式只调整系统首帧、页面背景、表面和文字对比，不改变苹果青绿品牌渐变的识别关系：

- 系统启动首帧：纯黑背景；
- 系统启动页不显示中心品牌图标；
- 品牌渐变页仍使用同一组 `#A8F3C8 → #5DDFB4 → #35B9B5`；
- 深色页面使用深色表面与浅色文字，禁止直接把浅色页面反相后产生刺眼的高亮块；
- 主操作仍保持青绿色识别，但应通过文字/边框对比确保可读性。

## 3. 排版规范

### 3.1 层级

优先使用 Material 3 typography，并保持以下语义层级：

| 层级 | 推荐语义 | 使用方式 |
| --- | --- | --- |
| 页面主标题 | `headlineSmall` | 页面顶部唯一主标题，粗体，可使用 `MintPrimaryDark` |
| 区块标题 | `titleMedium` | 词书、每日目标等区块标题，粗体 |
| 数字锚点 | `displaySmall` | 每日目标、计数等核心数字，粗体，使用 `MintPrimary` |
| 正文 | `bodyMedium` | 说明、引导和主要内容 |
| 辅助正文 | `bodySmall` | 等级、来源、补充说明 |
| 标签/状态 | `labelMedium` 或 `labelLarge` | “已选”、分类、短状态 |

### 3.2 文案与布局

- 页面顶部只保留一个明确主标题；不要堆叠多个同级大标题。
- 主标题下可放一行简短副标题，说明页面价值或下一步行动。
- 核心数字必须有单位或语义说明，例如“词”，不能只显示孤立数字。
- 关键操作使用动词，例如“保存并开始学习”，避免只写“确定”。
- 中文界面优先使用自然、短句式文案；不要把实现术语直接暴露给用户。
- 需要解释词书来源时，明确写“应用内学习分组，不是官方考试大纲”，不得暗示与中国官方考试大纲等同。

## 4. 间距、圆角与尺寸

以下值为默认基线；新页面只有在内容密度或无障碍要求确实需要时才可调整：

| 项目 | 基线 |
| --- | --- |
| 页面水平边距 | `20.dp` |
| 页面垂直内边距 | `24.dp` |
| 页面区块间距 | `14.dp` |
| 卡片内部边距 | `18.dp` |
| 词书卡片内部水平/垂直边距 | `14.dp / 12.dp` |
| 主要卡片圆角 | `24.dp` |
| 交互卡片圆角 | `18.dp` |
| 主按钮高度 | `54.dp` |
| 词书卡片最小高度 | `72.dp` |
| 品牌页中心图标 | `180.dp` |
| 应用内 Loading 图标 | `48.dp` |

圆角表达柔和和亲和力，但不能让所有元素都变成胶囊形。胶囊形只用于短标签、状态徽章或明确的连续控件。

## 5. 卡片与层次

### 5.1 卡片

- 卡片优先使用浅色表面，不使用厚重黑色阴影。
- 默认使用 `1.dp` 柔和边框配合圆角；选中卡片使用品牌色边框。
- 选中状态至少同时体现两种差异：背景/边框、单选控件、状态标签、文字或轻微动效。
- 卡片不得只依赖颜色表达选中状态，必须保留可读的文字或控件状态。
- 卡片内容按“标题 → 辅助信息 → 状态/动作”排列，避免信息四散。

### 5.2 高斯模糊与材质效果

高斯模糊不是默认装饰，而是有限使用的材质语言：

- 仅可用于品牌启动页、顶部浮层、底部浮层、弹层背景或明确需要与背景分离的半透明容器。
- 模糊应服务于层次和可读性，不能用于正文卡片来制造噪声。
- 模糊面板必须同时有半透明填充和足够对比度；不能只靠模糊承载文字。
- Android 版本或设备不支持实时模糊时，必须有静态半透明色的降级方案，不能出现空白或透明穿透导致文字不可读。
- 不在列表中的每张卡片重复使用大半径模糊，避免性能问题和视觉过度装饰。
- 当前 F1-01 页面以浅色卡片、透明度和边框建立层次；后续若加入高斯模糊，必须保持这种轻量原则。

## 6. 交互与动效

- 选中卡片动效：短时、柔和，建议约 `180ms`，使用平滑缓动。
- 动效只强化状态变化，不阻塞用户操作，不延迟页面可用时间。
- 滑条支持连续拖动并实时显示 `1..50` 的整数目标；不要依赖难以命中的离散刻度。
- 动效期间内容位置不能明显跳动；滑块拇指和数字显示应保持稳定。
- 保存成功应提供清楚的文字回显；不能只依赖 Toast 或颜色变化。
- Loading、空状态和错误状态都必须有明确内容，不得只显示旋转指示器。
- 尊重系统减少动态效果设置；减少动效时仍保留状态和层次信息。

## 7. 启动页与品牌资产

启动流程固定为三段：

1. **系统首帧**：浅色模式纯白、深色模式纯黑；使用透明占位资源，不显示中间居中图标。
2. **品牌启动页**：苹果青绿三段渐变，中心使用同款语言气泡/叶片标识，尺寸 `180.dp`，正中心对齐。
3. **主页面**：进入应用页面后继续使用同一组品牌色和轻量卡片语言。

补充约束：

- 桌面图标可以使用完整自适应图标；启动页中心图标使用简化的同款标识，不把完整方形桌面图标套在启动页中。
- MIUI 等 OEM 可能在系统极早阶段显示自己的小型应用标识；这属于系统启动层，不应通过修改应用内品牌页来补偿。
- 不得在启动页增加 ActionBar、标题或额外文案。
- 启动页不能出现深森林绿大面积背景、紫色、蓝色或与主页面割裂的旧主题。

## 8. 无障碍与可用性

- 可点击卡片、单选按钮、滑条和主按钮必须有清晰的语义描述。
- 触控区域应足够大，不能为了追求紧凑而缩小核心操作。
- 颜色不是唯一信息来源；选中、错误、成功必须有文字、图标、边框或控件状态辅助。
- 核心文字不得放在过度透明、模糊或低对比度背景上。
- 横向空间不足时允许换行或滚动，不得裁切词书名称和目标数字。

## 9. 禁止事项

以下做法需要视为视觉回归，除非先更新本规范并获得产品确认：

- 恢复紫色旧主题或使用深森林绿作为主背景；
- 随意替换品牌渐变色值；
- 将启动页中心图标恢复为完整桌面图标或任意放大到遮挡内容；
- 在系统白/黑首帧增加中心图标；
- 使用负 padding、负布局偏移或其他会造成 Compose 运行时崩溃的视觉技巧；
- 大面积重阴影、重模糊、玻璃拟态堆叠或营销式装饰；
- 仅通过颜色表达选中/错误/成功；
- 新页面自行引入未经定义的字体、颜色、圆角体系或间距体系；
- 将应用内学习分组描述为中国官方考试大纲或官方词表；
- 在未进行真机检查前宣称视觉一致。

## 10. 新页面验收清单

提交新的 UI 功能前，至少检查：

- [ ] 背景、卡片、主操作遵循苹果青绿令牌；
- [ ] 没有引入紫色、深森林绿或未定义的品牌主色；
- [ ] 页面标题、区块标题、正文和辅助文字层级清楚；
- [ ] 页面边距、卡片圆角、主按钮尺寸符合基线；
- [ ] 选中、成功、错误和 Loading 状态不只依赖颜色；
- [ ] 高斯模糊/半透明材质有明确用途，并有无模糊降级方案；
- [ ] 动效短、可中断、不造成布局跳动，并尊重减少动态效果；
- [ ] TalkBack/语义描述覆盖核心操作；
- [ ] 浅色与深色模式均检查；
- [ ] 真机冷启动和页面截图与本规范一致；
- [ ] 如需偏离本规范，先更新本文档并说明原因。

## 11. 维护规则

本文档是视觉基线，不是一次性设计说明。任何新增颜色、字体、材质、启动流程或全局间距，都必须先在本文档中定义，再进入代码。代码中的视觉常量应尽量集中为主题令牌或专用组件，避免在页面中散落新的魔法值。
