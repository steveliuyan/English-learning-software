## 0. 全局结论（三句话）

1. **词汇域的三个列表其实只有一个职责冲突**：`查词`（任意词，输入驱动）、`词书单词`（这一册有什么词，字母驱动）、`生词本`（我要处理哪些词，时间驱动）。三者都有各自的词行组件，但只有第一个职责是真正独立的——后两个是「一份数据两种排序」，可以收在同一页的两个视图里。
2. **打卡页被当成了词汇域与记录域的总入口**，这是本轮最严重的错位：收藏与错词的**唯一入口**是打卡页头部两条裸文字链，代码注释自己承认了这件事（`CheckInScreen.kt:57`「打卡页是收藏页的唯一入口」）。一个统计页承担了资产目录的职责，而它自己的内容（今日/本周/本月三套完成度）又与今日计划、学习记录逐字重复。
3. **学习记录域的两个页面合起来把同一天的完成度画了 4 遍**（今日计划进度卡、打卡今日卡、打卡完成度环、打卡 7 日条 + 本周条 + 月历），且「今日是否完成」在同一页有两套互不相容的判定口径。

## 13. 词汇域信息架构建议

固定四栏不可动；以下三案都**不新增功能**，只重排已有页面与入口。

### 方案 A（推荐）：三个入口 —— 查词 / 词表 / 我的词

| 入口 | 承担 | 形态 |
|---|---|---|
| **查词** | 任意词输入查询 + 最近搜索 | 今日计划顶部搜索条（现状正确，`TodayPlanScreen.kt:80`），保留阅读页/拍照页两个上下文入口 |
| **词表** | 当前词书的词按字母浏览（= 现「词书单词」） | 今日计划一条列表入口 |
| **我的词** | 一个页面四段：**收藏 / 生词本 / 错词 / 重学入口** | 取代「生词本」按钮位置；生词本、错词、收藏降为其内分段 |

- **收口逻辑**：`生词本`（要处理）与 `错词本`（会自己消失的 Again 派生）与 `收藏`（用户手动 pin）在数据上是三个不同集合（§9），但在**用户意图上是同一件事：「我攒下来的词，现在看看」**。合成一页多分段，入口从 3 个减到 1 个，打卡页卸掉资产目录职责（`CheckInScreen.kt:78-83`）。
- **词书单词与查词保持分离**：一个是"输入驱动"，一个是"整册浏览"，`GlobalVocabularySearchScreen.kt:52-57` 的注释已经论证过「刻意没有浏览词书」，这条边界是对的。
- 代价：① 新增一个分段容器（但每段就是现有 `WrongWordsScreen`/`FavoritesScreen`/`VocabularyScreen` 的列表主体，无新数据路径）；② 今日计划按钮从 8 减到 3（`TodayPlanScreen.kt:240-283`），打卡页头部重排；③ 三个 ViewModel 要在同一宿主并存，`AppScreen.kt` 的 if-else 链需为分段内部状态腾出一层（该文件已 2330 行，**这是最大实现风险**）；④ 需改的 connected 测试：`CheckInScreenTest`（头部三条链断言）、生词本/收藏/错词各自的入口测试。

### 方案 B（最小改动）：入口不动，把收藏/错词从打卡页搬到今日计划的分组行

- 做法：今日计划把「词书单词 / 生词本 / 收藏 / 错词」压成一条「我的词汇 ›」行（点开是四选一列表），打卡页只留返回（删 `CheckInScreen.kt:78-83`）。
- 优点：不新增分段容器，ViewModel 宿主结构不变，改动集中在 `TodayPlanScreen.kt` 与 `CheckInScreen.kt` 两个文件。
- 代价：收藏列表仍比现在多一层；「我的收藏」的反馈闭环（在详情里点收藏 → 立刻找到它）仍不闭合。

### 方案 C（激进）：生词本 + 错词合并成「待复习的生词」，收藏独立

- 做法：取消错词本页面，错词作为生词本内的「仍错着」派生视图（口径就是 `InternalLearningStatsDao.kt:103-112`）；收藏与查词历史并入设置页新增的「我的词汇」分组。
- 优点：正面解决 §9 的"分不清"——用户只面对"我要处理的词"一个概念；页面总数从 8 降到 7。
- 代价：**语义变更风险最高**。错词「自动消失」、生词「保留到手动标掌握」是两个已被验收标准钉住的生命周期（`RoomWrongWordsRepository.kt:10-13` 注释、`VocabularyScreen.kt:63`），合并展示容易让人误读规则；且收藏入口进设置页会让它离动作更远。**不推荐本轮做**，可记入 `docs/decisions/` 作为后续候选。

**推荐 A**：它是唯一同时解决「裸文字链入口」「打卡页越职」「今日计划 8 按钮膨胀」三项的方案；风险集中在 `AppScreen.kt` 宿主分层，可分批实现（先把分段容器建起来、再摘打卡页的链、最后收今日计划）。
