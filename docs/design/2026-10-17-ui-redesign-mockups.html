薄荷玻璃 · 设计系统重设计稿

这是 UI 重设计轮批 1 的视觉基线，不是生产代码。所有取值都是本仓库当场算过的：色值来自 ui/theme/AppPalette.kt、MintPalette.kt 与 docs/design/visual-style-guide.md；对比度按 WCAG 2.x 相对亮度公式现算。 设备框按 360dp 真比例绘制（1px = 1dp），字号与间距用同一套变量，缩放控件会同时作用于四屏。

一句话结论：问题的根源不是薄荷玻璃不好看，而是没有装配点——全仓没有一处 MaterialTheme(...)，206 处 MaterialTheme.typography 吃的是 Material 3 默认字号，与已定义的薄荷六阶无关；深色模式也因此没有落点（DarkColorScheme、 isInDarkTheme 全仓 0 命中）。本稿先定 token 与组件，再让 33 屏逐个接上。

6.2 三案对照：要不要更「像应用图标」（已定 B 案 · 双色层次，2026-10-18）

你提到想要扇贝那种「里面有自己设计的图案、像应用图标、挺高级」的图标。先把一件事说清： 公开可查的竞品分析里，扇贝老版本恰恰是「以文字为主、少用图标」 （站酷 · 扇贝/百词斩竞品分析）， 所以这轮不能照着"抄扇贝的图标"——能借的是那种图块化 + 有内部层次的观感， 而不是它具体的图形。下面三案用的是同一套造型骨架，只差容器与内部层次， 你只需要判"要几层"，不必判"画得好不好"（真机与深浅两套都由顶栏控件现切）。 拍板结果 2026-10-18：选 B——入口层拿渐变容器 + 双色层次，行内仍是单层描边； 过程、实测数字与许可影响见 docs/decisions/2026-10-18-ui-redesign-icon-duotone.md。下面三案保留作选型依据，A/C 不再实施。

方案 A · 单色描边 + 域色实底（现稿定的方案）

三案共同的红线，不随选型变：单族造型、24dp 网格、统一描边重量、容器 12dp（B/C 入口块可 14dp）、 禁止 emoji 与含字徽标、图形对比 ≥3:1 当场算、装饰性图形 contentDescription = null、 有语义的图标按钮必须有真实读屏名。选型改的只是"容器与内部几层"，不动这些。

这一版顺手改掉了一个我实测出来的坑：浅色模式若把渐变亮端直接设为域色 base，白描边会不合格—— AI #2EC99C 上白字 2.11:1、复习 #FF9F0A 上白字 2.06:1，连图形 3:1 的下限都不到， 薄荷与橙恰恰是最"好看"的两个域。因此 B/C 的渐变亮端一律取 deep 混 35% base（不是 base 本体），实测七域白描边落在 3.17:1 ~ 6.26:1，最差是 AI； A 案容器本就用 deep，白描边 4.02:1 ~ 9.12:1。深色模式容器改用亮域色 + #06231A 字形，实测 5.96:1 ~ 9.82:1，最差是危险。 C 案还额外叠了一层白色高光，那层压在哪枚字形上要逐枚实测——这是 C 的隐性成本之一。
