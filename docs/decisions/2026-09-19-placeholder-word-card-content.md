# 决策：F1-03 词卡内容使用应用自撰占位内容

- 日期：2026-09-19
- 阶段：Stage 1 / F1-03 词卡与反馈
- 状态：已决定（用户确认）

## 背景

F1-03 要求词卡展示「单词、IPA、词性、中文释义」，例句与词形变化「有资源时显示」。执行前的事实状态：

- `app/src/main/assets/wordbooks/metadata.json` 六本词书的 `totalWords` 全为 `0`，并注明「词条尚未随本任务打包」。
- `docs/third-party-notices.md` 明确：「当前仅保存六本应用内学习分组元数据，**不使用、不下载、不打包任何词条正文或中文释义**」「词条正文在完成逐项许可核验前禁止商业分发」。
- `FixturePlanCardSource` 的 `newCardIds`/`dueCardIds` 返回空列表，因此今日计划恒为 `newTarget = 0`、`dueTarget = 0`——**真机上不存在任何可学习的卡片**。

也就是说，若不同时解决「计划里有卡」和「卡里有内容」两件事，F1-03 的词卡与三档反馈无法在真机上被验证，只能停留在单测层面。

## 候选方案

### A. 先接入第三方数据集再实现 UI
NGSL/NAWL 1.2 为 CC BY-SA 4.0，理论上可带署名与 ShareAlike 条件再分发，但：

- 该数据集**不含中文释义**，中文释义仍需另寻来源或自行撰写，许可链并未因此闭合；
- CC BY-SA 4.0 的 ShareAlike 会对本应用的数据分发方式产生额外约束，属于独立的数据与许可工程任务；
- CEFR-J 1.5 亦为独立来源，等级标注与词条正文是两件事。

结论：这是一次独立的数据接入任务，周期明显长于 F1-03 本身，且中文释义来源仍需单独决策。**本轮不采用，但它仍是长期正确的终态。**

### B. 应用自撰占位内容（选定）
由应用自行撰写一小组基础词条（单词、IPA、词性、中文释义、例句）作为**占位内容源**：

- 内容为应用原创，**不来自任何第三方数据集**，不引入新的许可依赖，也不受 ShareAlike 约束；
- 词卡内容经 `WordCardSource` 接缝注入，与计划卡 ID 来源解耦，替换为许可核验后的数据集时不需要改动 UI 或存储层；
- 使 F1-03 与后续 F1-04 具备真机可验证性，符合本项目「优先交付可运行、可见、可真机验证」的节奏。

风险：占位内容可能被误认为正式词书随包发布。**选定**，并以下述手段缓解。

### C. 只交付反馈内核，不引入任何内容
满足「零许可风险」，但真机上依旧无卡可学，F1-03 交付物不可见、不可真机验证，F1-04 亦无法验证。**否决**。

## 决定

1. 词卡内容经 **`WordCardSource` 接缝**消费；UI 与存储层只依赖该接口与 `WordCard` 模型，不感知内容来源。
2. V1 实现为 **`PlaceholderWordCardSource`**，内容为**应用自撰**的 12 个基础词条，无第三方数据参与、无下载、无网络。
3. 卡 ID 采用可逆命名 **`placeholder:<wordBookId>:<lemma>`**，使「同一拼写在不同词书各自计进度」在 ID 层面即成立（对应 AC1-06），且一眼可辨为占位数据。
4. 类型名、常量名一律带 `Placeholder`/`PLACEHOLDER_` 前缀，避免与未来正式内容实现混淆。
5. `docs/third-party-notices.md` 登记占位内容条目：来源为应用自撰、无第三方许可依赖、数据流为仅在设备内读取、**发布前必须替换为许可核验后的词条数据**。
6. 计划卡来源（`PlanCardSource`）改用事件存储的真实新词/到期划分，使占位卡能进入今日计划并被学习。

## 影响

- **许可**：不引入任何第三方词条正文或中文释义，台账中 NGSL/NAWL 与 CEFR-J 条目的结论（未分发词条正文）仍然成立。
- **产品**：真机首次进入今日计划会看到占位词卡，属于**开发期可见性**而非正式词书内容；替换数据前不得发布。
- **架构**：内容源、计划卡来源、事件存储三者边界独立，后续接入许可数据集只需新增 `WordCardSource` 实现并替换 Hilt 绑定。
- **替代方案**：若最终无法获得可再分发的中文释义数据，`WordCardSource` 也可实现为「仅在线查词、不打包词条」，无需改动事件层与 UI。
