# 决策：词卡改为「回忆 → 揭晓 → 评分」流程（2026-10-14）

状态：已批准（用户 2026-10-14 指示「就按这个方案推进吧，先改 Spec 和决策文档」）。

## 背景

用户在真机使用中指出：词卡页一进卡片就直接显示中文释义，而主流背词产品（Anki、墨墨背单词、不背单词等）都是先回忆、再看答案、最后评分。原阶段 1 Spec F1-03 写的「词卡展示单词、IPA、词性、中文释义」是当时的默认设计，实现与 Spec 一致，不是代码缺陷，而是学习设计缺陷：

- **回忆 vs 辨认**：释义可见时点「认识」，测到的是"认出"（recognition）而不是"想起"（recall）。间隔重复的三档评分依赖真实的提取强度，答案先露出会系统性高估记忆强度，导致 FSRS 给出偏长的复习间隔，用户在实际需要提取的场景（阅读、听力）中仍想不起来。
- **提取练习效应（testing effect）**：先尝试回忆再核对，本身就是一次提取练习，记忆收益高于被动阅读释义。
- **行为一致性**：目标用户（四六级、考研）普遍熟悉 Anki 式流程，先回忆后揭晓符合预期心智。

## 候选方案

- **A（批准）：统一的回忆-揭晓-评分流程。** 卡面只露单词、IPA、词性，英文例句作为语境线索保留显示；中文释义与词形变化藏在一个「显示释义」动作之后；三档评分按钮揭晓前后均可见可点（已确定判断时不必强制多一步）；新词卡与复习卡完全同流程；不提供开关。
- **B（否决）：评分后才显示释义。** 用户最初设想的形态。缺点：反馈按钮与释义共用一次点击节奏，模糊/认识档需要先评分才能核对答案，打乱"核对→评分"的自然顺序；评分时看不到答案反而更容易凭印象乱点。
- **C（否决）：设置开关，允许选择直接显示释义。** V1 增加设置面与维护成本，且两个流程都会分流测试路径；「先回忆」在科学上严格占优，没有默认之外的必要场景。若阶段 5 无障碍走查发现揭晓步骤对特定人群构成障碍，可在 UI 重设计轮重开此决策。

## 决定与影响

1. 修订 `docs/specs/01-vocabulary-learning-and-review.md` F1-03：卡面展示规则、揭晓动作不计完成度、离开重进后回到隐藏态、评分按钮保持可见、无设置开关；新增 AC1-20～AC1-22 对应验收。
2. 实现影响仅限 UI 层：`WordCardViewModel` 的 Ready 状态增加 `meaningRevealed` 字段（每张卡独立、未提交反馈重进后复位）；`WordCardScreen` 将 `word_card_meaning`、`word_card_inflections` 藏入揭晓分支，新增「显示释义」按钮。三档反馈、事件 ID 幂等、FSRS 映射、完成度与解锁判定全部不变。
3. 不改动学习事件与数据库 schema：揭晓不是学习事件，无持久化需求，应用重启后回到隐藏态与"离开重进复位"规则一致。
4. F1-06 详情页规则不变：评分后（模糊/忘记了默认开启时）进入只读详情页看完整解释，形成「回忆→揭晓→评分→（可选）详解」的递进。
5. 词卡自动朗读（阶段 3 TTS 行为）保留在卡面，不属于被隐藏内容。

## 验收口径

- AC1-20：揭晓前卡面无中文释义与词形变化；点击「显示释义」后展示释义及有资源时的词形变化。
- AC1-21：只揭晓不评分——学习事件表零新增、当日完成度不变、卡片保持未完成；离开并重新进入该卡后释义回到隐藏状态。
- AC1-22：新词卡与复习卡运行同一揭晓流程；揭晓前后三档评分按钮均可见、可提交。
