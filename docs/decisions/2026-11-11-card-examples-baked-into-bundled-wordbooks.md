# 例句改为离线烘焙进随包词书（取代运行时 AI 生成 + 本机缓存）

- 日期：2026-11-11
- 状态：已采纳（用户 m00140 在 A/B/C 三案中选 A，m00210 定覆盖率「全部」）
- 关联：F1-08、AC1-28…AC1-33、F2-07（原 AC2-16 已删除）

## 背景

随包十册词书共 45,290 张卡，`example` 字段实测只有一个取值「暂无例句」（判据见 `ui/WordBookContentPlaceholders.kt`），
用户提供的 Excel 源表也**没有例句列**。原 F1-08 的设计是：运行时由用户自己配置的 AI Profile 逐卡生成、结果落本机缓存
（DB v33→34 的 `card_examples` / `card_example_backfills`、批量补齐 ViewModel、成本提示、出站确认、详情页「AI 补一句例句」）。

用户 2026-11-11 否决了这条路线：「例句不应该直接加入到词书里面吗？就是不是缓冲哦，就有点像原生的一样我记得我这些词书都是一个excel表格来的」。

## 候选方案

- **A 离线烘焙进随包资产**：在仓库产线里一次性生成，写进 `book.json` 的 `example`/`exampleZh`，随包分发。运行时零请求、零缓存、零出站。
- B 运行时生成 + 本机缓存：原 F1-08。用户没有 Key、没网、或换设备时看不到例句；每次学习都对第三方出站；缓存表与批量任务都是新表面积。
- C 两者都要：同一功能两条取值链，成本与不确定性翻倍。

## 决定

1. 采用 **A**。例句只在离线产线生成，合并进随包 `book.json`；运行时 `WordCard.example` / `exampleZh` 是唯一取值来源。
2. 产线输入是用户提供的十册 Excel 原件。**核对结果**：解析出 45,290 张卡，逐册词条集合与随包资产完全相同（0 新增、0 删除、0 重复），所以可以按词条为键只补两个字段，不重导整套词书。
3. 产线分两段：`tools/wordbooks/generate_examples.py` 产出 sidecar `tools/wordbooks/examples/<bookId>.json`；`tools/wordbooks/apply_examples.py` 幂等合并进 `app/src/main/assets/wordbooks/<bookId>/book.json`，**只动 `example` / `exampleZh`**。
4. 覆盖率：**全量 45,290 张**（用户口径「全部」）。实在生成不出来的卡保持「暂无例句」并在产线报告里逐条列出。
5. 例句是 AI 生成文本，属于「未核验许可的语料不得打包」的管辖范围：必须登记模型名、提示词版本与生成日期，并在第三方台账记录「例句为 AI 生成文本」以及所用服务条款是否允许把输出随包分发；条款不允许则不得发布该包。
6. 例句不进入备份包（它在资产里，不是用户数据）。

## 影响

- **体积**：十册 `book.json` 现 41.6MB，预计增至 50–53MB；预算上限 60MB（F1-08）。
- **运行时**：无新表、无 Room 迁移（DB 停留 v33）、无新 ViewModel、无新路由，`ScreenTransitionContractTest` 不重算。
- **失败面**：从「生成失败 / 超时 / 取消」退化为「资产里没有例句」，按缺失模块整体隐藏（AC1-28），不需要成本提示、出站确认、暂停续跑与重试界面。
- **不可在用户侧重生成**：换模型或改提示词必须重跑产线、发新版本包，`metadata.json` 的 `dataVersion` 递增。
- **规格变化**：F1-08 重写为「例句的离线烘焙与随包分发」，AC1-29…33 重写；F2-07 改为「例句不再属于运行时 AI 消费方」，AC2-16 删除。
- **一次性产线成本**：45,290 请求 ≈ 11.3M 输入 token / 3.2M 输出 token，按 gpt-4o-mini 参考价约 $3.6；时间取决于并发与端点速率。
