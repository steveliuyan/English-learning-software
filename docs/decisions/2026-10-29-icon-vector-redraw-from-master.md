## 背景

`docs/design/icon-master/` 的 28 枚「绘画感」母版已 28/28 通过 v3 审计并获用户认可，但运行态字形仍是
`ui/components/AppIcons.kt` 的 24×24 三层矢量，除了 2026-10-28 裁决 D1（强调层真正进画布）之外，
几何本身没动过：多数字形仍是「一个圆/一个方框 + 几根 2px 线 + 一根细强调条」。

两条源码事实决定了重绘该往哪儿使劲：

1. `EntryIconBadge` 只有 `EntryIconTone.Gradient` 档画三层；`EntryIconTone.Tint` 弱档与
   `InlineIconBadge`（底部导航、今日计划入口行、`NotConfiguredCard`）都走 `AppGlyphLayer.StrokeOnly`。
   也就是**生产界面上最常见的小尺寸形态只有 `strokePaths` 一层**。
2. `accentPaths` 恒为不透明单色，画不出母版那种「浅面/深面/高光」三段明度，最多做「一块实心 + 一个小芯」。

所以「绘画感」不能靠再加一层或加色，只能落在**描边层的形**与**强调层的块面配重**上。

## D6 结案：深套强调层保留 `onBrand`（方案 A）

2026-10-28 的 D6 待定项问的是：深套 `Gradient` 档的强调层要不要从 `onBrand` 换成域色（`base` / `light`），
以便和浅套一样「同域同色」而不是中性墨。实测（`IconBadgeContrastContractTest` 同一套 WCAG 相对亮度公式，
按渐变两端 + 底幅合成后的最差处取值）否决了这个方向：

| 候选 | 7 域中最差值 | 是否过非文本 3:1 |
| --- | --- | --- |
| 域 `light` | 2.31:1（`Review` 琥珀） | 否 |
| 纯白 | 2.82:1（`Review`） | 否 |
| `onBrand`（现行） | 已由既有契约逐域钉在 3:1 以上 | 是 |

根因是深套的域色本身就是浅底（`DomainDark.deep` 与 `base` 合一），底幅又是 `onBrand` 以 0.30 稀释出来的，
浅色强调层压在浅色底幅上必然掉到 3:1 以下。**决定：深套强调层维持 `onBrand`，零代码改动**；
「同域发色」在深套由渐变底本身承担，强调层只负责「实心重述」。B 方案（把 `DuotoneFillAlpha.Dark`
从 0.30 抬到 0.42 以拉开底幅）与 C 方案（逐域手调 `light`）同时否决：前者会把深套底幅整体提亮、
削弱 §2.1 的玻璃质感，后者是在 7 域 × 2 主题上开 14 个例外。

## 决定：先做三枚样板，再定批量口径

样板取「跨三个不同域、三种不同造型骨架」的三枚，覆盖最容易翻车的三种情形：

| 母版 | `AppIcon` | 域 | 本轮新增的「绘画感」笔画 |
| --- | --- | --- | --- |
| `03-clock.png` | `Clock` | Review | 盘面右下内缘一道**阴影弧带**（`M18.8 12A6.8 6.8 0 0 1 12 18.8L12 17.4A5.4 5.4 0 0 0 17.4 12Z`），与轴心、指针块一起构成「受光在上左」的体积 |
| `01-book.png` | `Book` | Learn | 底幅由「左页半幅」改为**左右两页双面**，描边层补一条**页块下沿**（`M5.4 17.6h13.2`），书脊与书签带留在强调层 |
| `20-gear.png` | `Gear` | Settings | 由「三轨 + 单旋钮」改为**三轨 + 双旋钮**（新旋钮 `CircleStroke(8, 7, 2.2)`，轨 3 贯通到 `h16`），强调层补第二枚旋钮芯与一条已调轨段 |

三枚都保持原有语义骨架（时钟仍是环 + 指针、书仍是合上的书、设置仍是滑杆），因此不涉及
`docs/decisions/2026-10-18-ui-redesign-contrast-and-icon-layer-rulings.md` 的枚数/顺序/用途清单，
也不动 `StrokeOnlyIcons` / `AccentlessIcons` / 容器几何。

## 批量口径（样板通过后按此推广，逐条可判）

1. **造型承重层是 `strokePaths`**：每枚至少含一段弧或曲线命令（`A`/`a`/`C`/`c`/`Q`/`q`），
   并至少一条「内部结构线」（书脊、页块、镜片、盘缘之类），因为 `Tint` 弱档与行内徽标只看这一层。
2. **底幅只放一个大面**：`fillPaths` 覆盖识别区域内部，不切碎成多个小片（重叠半透明会在 40dp 上出现补丁感）。
3. **强调层 = 一块有机实心面 + 一个小芯点**（2–3 条路径），实心面用闭合折线/弧带而不是 1.6px 细条；
   细条在 22dp 下与描边同宽，等于白画一层。
4. **不改四件事**：24×24 画布与 2px 描边、枚举与豁免表、容器尺寸/圆角/渐变、强调层取色规则（见 D6 结案）。

## 影响

- `ui/components/AppIcons.kt`：`Clock` / `Book` / `Gear` 三枚的三层几何按上表重绘，来历注释改写为
  「原创自绘（B 案度量）」——母版与矢量都是本项目自绘，不引入第三方路径；`docs/third-party-notices.md`
  的 `app-authored-ui-icons` 结论不变。
- 测试：`AppIconsStructureContractTest` 增「插画样板锚点」用例，钉住三枚的新增笔画与强调层枚数，
  并用旧几何做合成负例；段数守恒、分层形状、枚数/顺序用例照旧覆盖。
- 不在本轮范围：其余 30 枚（含 5 枚豁免与 3 枚传输控件）的批量重绘、母版本身、渲染器与容器。
