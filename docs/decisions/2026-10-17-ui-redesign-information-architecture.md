# 决策记录 · UI 重设计轮信息架构（2026-10-17）

## 背景

用户认为现状「所有页面不统一、太乱、有些页面根本不该出现这些东西」，要求逐屏分析内容归属并把界面做简洁。
5 个只读子代理按域完成 33 屏逐屏审计（见 `docs/design/2026-10-17-content-placement-audit.md` 与
`docs/design/content-placement/G1–G5`），主控回源码复核全部高影响主张后，把结论分成两类：
**需要拍板的信息架构取舍**（六条）与**不需要拍板、按既定规范直接修的缺陷**。
本记录只登记用户在 2026-10-17 给出的裁决与其边界，不改任何业务规则。

前置约束（本仓库既有，不因本轮松动）：底部四栏与 `AppTabTest` 钉住的顺序不动；
FSRS 复习、每日计划快照、严格/宽松解锁规则、备份认证与配对语义、删除级联确认，一律不碰；本轮不新增功能。

## 六条裁决

### ① 词汇域入口 → 采纳方案 A

三个入口收成 **查词 / 词表 / 我的词**，其中「我的词」把 **收藏 · 生词本 · 错词** 合成一页三段（分段容器），
不再让用户为"我攒下来的词"跑三个页面。

- 依据：收藏与错词的全站唯一入口原本是打卡页标题右侧两条裸文字链（`CheckInScreen.kt:78-83`），
  即一个统计页当了词汇资产目录；生词本 / 错词本 / 收藏三个集合在「标记不认识」那一刻是同一批词，
  界面上没有任何文字解释区别（`VocabularyScreen.kt:63` vs `WrongWordsScreen.kt:90`）。
- 代价与风险：`AppScreen.kt` 实测 2424 行，新增分段容器与三个 ViewModel 同宿主并存是本轮最大实现风险；
  入口迁移必须**先建新入口再摘旧入口**，受影响的 connected 断言（含 `CheckInScreenTest`）逐条列清单。
- 落选方案：B 只搬家不合并（收藏反馈闭环仍不闭合）；C 生词本与错词合并为「待复习的生词」
  （语义风险最高：错词自动消失 vs 生词手动标掌握，两者都已被验收标准钉住，`RoomWrongWordsRepository.kt:10-13`）。

### ② 设置页 → 收成 4 组 9 行，两条「后续版本」占位行全删

保留 **学习 3 / AI 与语音 2 / 外观与关于 2 / 数据与安全 2**，页头一句隐私摘要；
删除「账户」整组（含昵称与头像占位）与只为占位行存在的「阅读」整组；`SettingsPendingRow` 随之下线。

- 依据：AGENTS.md 明确「无账户、无隐式云同步」，占位行承诺的是方向上被禁止的能力；
  现状 7 组 14 行里有 2 行完全不可点、各占一组（`SettingsScreen.kt:186-192`、`:224-237`），
  「学习提醒」错挂在 AI 组（`:214`），「关于」挂在「账户」组内。
- 「学习提醒」无论最终几组都必须落在「学习」组——不照抄实现里的归属错误。
- 资料卡里的「今日计划：新增 N · 复习 M」一并删除（进度数字归今日计划页一处权威呈现）。

### ③ 打卡页 → 回归统计职责，头部两条裸文字链移出

随 ① 落进「我的词」。打卡页只保留「坚持与统计」视图（连续 / 周 / 月 + 一份今日结论），
删掉与今日计划逐字重复的第二张今日完成度卡，把三套同日完成度收成两套。

- 附带裁决（用户提出）：**打卡页可以有一张"华丽动态"的坚持动画**。本轮**不做**，
  原因是动效属于视觉定稿之后的独立批次，且动效需要单独的对齐 `prefers-reduced-motion` 与
  TalkBack 朗读口径；已登记为批 3 之后的候选项，先定 UI 再谈动画。

### ④ AI 主页 → 采纳推荐：默认展开「现在能用」，未上线压成一条折叠行

主页唯一职责是"选能力"。状态徽章要真实（现在代码里解释卡还写着「长难句分析与生图正在开发」
`AiLearningScreen.kt:312`，与 `AiFeature.kt:85/97/110` 的 `implemented = true` 矛盾）；
未配置的 AI 必须给「去配置 ›」出口，不再是只有一句文案的死页；「词文串学」这类未上线条目移回折叠组或改直达。

### ⑤ 阅读主页 → 版面部分采纳，能力部分另立决策

**已定（版面）**：主任务「今天读什么」上提到第一屏；外刊 Feed 改独立二级层（带返回，与粘贴导入同层），
不再原地内联展开（现状无条数上限也无收起入口，`ReadingAccessScreen.kt:222`、`:349-359`）；
类型与长度偏好下沉「生成前参数」；「AI 生成」与「换一篇」合成一个动作。

**已定（能力）**：用户提出"外刊除了 AI 生成，应该真的有在线搜索能力，让 AI 来搜索汇总"。事实核查见下节
——Feed 现在就是真实联网抓取，只是白名单里只有一个源。用户在 2026-10-17 选定 **B 路线：扩白名单源**，
排在 UI 轮三批之后作为内容面独立小批，**不进本轮 UI 重设计**。

### ⑥ 备份与危险项 → 采纳推荐

「留档 / 认证导出 / 换机恢复」合成 **1 个「备份与恢复」入口**，进子页三节；
「删除全部学习数据」下沉到该子页末节，级联条数 + 二次确认规则一字不改（`AppScreen.kt:1699-1730`）。
同屏还须改掉与自身功能矛盾的旧文案（「当前包不可用于认证恢复，F4-04 完成后才支持恢复」
`BackupExportViewModel.kt:141-143`）与用户界面上的开发者术语（`F4-04`、「AI Profile」、「Salvage 包」）。

## 扇贝单词作为参考：借什么、不借什么

用户点名扇贝单词「背词方法不错、页面简洁」。据公开资料核对后，本轮只吸收**版面与信息架构层面**的三点，
不引入其商业化结构与内容授权依赖：

**借（与我们的审计结论同向）**

1. 首屏只服务"今天做什么"：扇贝首页核心区是「开始学习」入口 + 今日新词/今日完成，
   打卡天数与掌握词数作为激励数字放在同一屏的次要位置，延伸能力（口语/听力/阅读/炼句）压在按钮之下。
   这正好印证我们把今日计划的 8 个整宽按钮收成「1 个 CTA + 一组入口行」。
   **激励数字的归属仍按 ②③ 的裁决**：累计打卡/掌握词数留在打卡页，今日计划页 Hero 只报今天的量，
   避免"同一数字三屏各说一遍"的返工。
2. 功能收进二级层以保一屏简洁：扇贝把大部分能力放到二级菜单，代价是低频功能路径变深——
   与我们的 ⑤（Feed 下沉独立二级层）、⑥（备份收一个入口进子页）同一手法。
   反面教材也现成：扇贝把「查词」放在标题栏右上角被公开批评为核心功能位置不当，
   所以 ① 里**查词保留为词汇域一级入口**，不下沉。
3. 「我的」页用文字链 + 小按钮提示可点击、功能点分散均匀：与我们把入口行统一成
   「彩色图标 + 一行主副标题 + ›」的组件口径一致。

**不借**

- 首屏放课程/商城/banner 导流（扇贝被公开评价为"过于商业化、降低体验"，且专门占一个 tab 主页宣传）——
  本产品无内购、无广告，也不留任何导流位。
- 完成学习后强制走分享与手帐步骤、且不给返回箭头（App Store 上有明确差评）——
  我们的词卡/打卡收口必须始终可见返回入口。
- 贝壳/同桌/小组等社区与虚拟货币机制：属新增账号与社交能力，AGENTS.md 要求未经确认不得添加。
- 柯林斯高阶词典授权与词根词源库：属内容资产，未通过许可核验前不得接入；
  词根/派生展示继续只用现有词书自带字段。

## 外刊在线检索：已选 B 路线（扩白名单源，排在 UI 轮之后）

事实基线：外刊 Feed **现在就是真实联网抓取**，不是 AI 生成——
`ReadingAccessViewModel.kt:190-227` → `FetchArticleUseCase.kt:81-123`（RSS 列表 + 正文 GET）
→ `ArticleFeedParser` / `ArticlePageParser` → `articles` 表（判别列 `sourceType`）。
来源注册表 `ArticleSourceRegistry.kt:29-57` **只登记 `voa-learning-english`**（公有领域），
`match` 强制 HTTPS + host 精确相等 + `/a/` 前缀。全仓库不存在任何服务端网页搜索或开放抓取，
也没有 tools/function_call 机制（`AiRequestPolicy.kt:7` 明确拒绝）。

因此"让 AI 去搜索并汇总"要动的不是版面，而是三条既有硬约束：
`docs/specs/02-reading-and-ai-content.md:51`「禁止按任意 URL 抓取，禁止用户自定义抓取目标」、
`docs/decisions/2026-09-24-article-source-licensing.md:21-24` 已**明确否决**"开放按 URL 抓取任意网页"、
`AiChatRequestBuilder.kt:45-68` 请求体字段硬编码白名单（不含 tools）+ AGENTS.md:54「拒绝任意工具调用」。
另有版权面：`docs/third-party-notices.md:403` 规定"未通过核验前抓取路径不得合并进发布构建"，
而主流外刊（经济学人/纽约时报等）不可转载。

| 路线 | 做法 | 得到什么 | 代价 |
|---|---|---|---|
| A 本轮只动版面 | ⑤ 的版面裁决落地，检索能力单列 | 一屏只回答"今天读什么"，Feed 可返回、不撑爆首页 | 「每天读真实外刊」的丰富度不变（仍是 VOA 一源） |
| B 扩白名单源（我建议的下一步） | 再登记 2–3 个许可可核验的免费/公有领域英语学习源，每源一条 `ArticleSourceRegistry` + 解析器适配 + 台账 8 字段 | 体验上就是"真的每天上线新外刊"，且不碰任何安全约束 | 需新决策记录 + 逐源许可核验 + AC 矩阵补非空证据行，属内容面独立小批，不进 UI 轮 |
| C 真做 AI 检索汇总 | 由用户 Endpoint 侧的检索能力（或我们代查）返回结果并汇总 | "想要什么主题就有什么文章" | 必须突破上面三条硬约束 + 版权与不可信内容校验全部重做 + 多数 OpenAI 兼容 Endpoint 并不提供检索工具；且抓取对象不可控，与"本地优先/隐私"口径冲突 |
| C′ 折中 | 不新增出网对象：AI 只对**已由白名单源抓到并落本地的文章**做摘要/改写/主题扩展，走现有 AI 生成链路与域名确认 | 得到"汇总感"，出网面与凭据面零扩张 | 素材仍受限于白名单源；需修订阶段 2 Spec 的一条 AC |

**裁决（2026-10-17，用户选定）**：走 **B**。理由与执行边界：

- B 是唯一**不松动任何安全与隐私硬约束**就能得到"每天上线新外刊"体感的路线：A 只解决版面，C 要同时突破三条既有禁令
  并承担不可控抓取对象的版权与不可信内容风险，C′ 只是 B 落地后可叠加的增益项，不是替代。
- 范围：在现有 `ArticleSourceRegistry` 里**逐源登记 2–3 个许可可核验的免费/公有领域英语学习源**（候选以「许可证或官方条款明确允许转载/可公开抓取」为准入门槛），
  每源一条注册项 + RSS/正文解析适配 + `docs/third-party-notices.md` 台账 8 字段 + `docs/ac-traceability-matrix.md` 非空证据行。
- 顺序：**排在 UI 重设计三批之后**，作为内容面独立小批；不与本轮共用分支，避免把内容准入审查混进视觉改动。
- 本轮（UI 轮）不碰 `ArticleSourceRegistry`、抓取白名单、AI 请求策略中的任何一条。
- 动工前仍需一次独立的许可核验与决策记录——公开条款要逐源实际读，不得凭"看起来是免费源"合并进发布构建
  （`docs/third-party-notices.md:403` 的门槛对每个新源同样适用）。

## 词卡内容深度：本轮不扩，只用现有字段

用户点名扇贝的"背词方法"，其中被问到的是词根词源、真题例句、释义深度这类内容增强。裁决是**不排批次**：

- 词卡与词卡详情的展示内容**继续使用现有词书自带字段**（释义、例句、音标、派生/短语等已在库中的项），
  本轮只调"哪些内容留在卡上、哪些移交详情"的归属（见审计 §5 第 3、4 屏）。
- 原因：词根/词源库与真题语料属**内容资产**，未通过许可核验前不得打包、下载或发布（AGENTS.md 发音、OCR 与资源一节），
  而"补充内容"会同时牵动数据模型、迁移与备份范围——那是内容与数据层的工程，与本轮"把界面做简洁"不同一条线。
- 不做的代价：词卡的信息密度仍受限于所选词书本身；若后续要接词根库，须先立独立决策记录与许可台账，再排批次。

  `prefers-reduced-motion` 与 TalkBack）、词卡内容深度扩展（需先过许可核验）。三项都不构成 UI 轮的验收项。
- 实施前必须先改 `docs/specs/`（阶段 1 与阶段 2 各涉及一处呈现口径）与本记录，再动代码——
  视觉风格指南 §11 的文档先行规矩不因"只是搬家"而豁免。
- 不新增依赖（`app/build.gradle.kts:163-165` `dependencyLocking` + 两份既有计划均写明不新增依赖）；
  图标继续走 `AppIcons.kt` 内嵌 Material Symbols 路径数据（Apache-2.0，须登记台账并通过 `verifyThirdPartyNotices`）。
