# 阶段 5：发布质量、可访问性与许可证治理 Spec

## 目标

证明应用在真实 Android 环境中具备可用性、离线可靠性、隐私边界、资源合规性与可发布质量。

## 前置

阶段 0–4 的范围已实现或明确裁剪；第三方依赖台账完整。

## 范围

### F5-01 质量门禁

- 为每项阶段验收标准建立可追踪测试：单元测试、数据库迁移测试、集成测试、设备/UI 测试或明确的手工验证脚本。
- 重点负向测试：重复反馈、跨日/时区、断网、AI 错误、AI Key 脱敏、缓存篡改、图片未确认上传、备份认证失败和导入原子性。
- 建立发布前检查：静态检查、单元测试、UI 测试、依赖漏洞检查、许可检查、APK/AAB 构建验证（已纳入 `checkReleaseReadiness` 的 `verifyReleaseArtifact`）。签名验证依赖用户场外提供的发布 keystore（决策 2026-10-15 §3）：配置存在则签名并核验，缺省产出未签名包并如实登记 TODO-USER，不得谎称已验签。「发布构建中通过」（AC5-01）的口径=单测全绿 + release 构建成功 + 产物密钥扫描绿，不强制 release 变体重跑全量单测（决策 §6）。
- 门禁聚合任务（已落地）：root `checkReleaseReadiness` = `verifyThirdPartyNotices` + `verifyAcTraceabilityMatrix`（docs/verification/ac-traceability-matrix.md，51 条 AC 证据行非空）+ `:app:testDebugUnitTest` + `scripts/secret-scan.sh`（自测：`scripts/secret-scan-selftest.sh`）。SP-E 将把 release 构建与签名验证挂入同一任务。

### F5-02 性能与可靠性

- 在阶段 0 确定的最低支持设备上定义并测量：离线冷启动、今日计划读取、词卡翻页、单词查询、学习事件写入、大型备份校验与恢复的性能目标。
- 性能阈值的**测量形态必须与承诺形态一致**（2026-11-06 批 B 补写）：`docs/verification/perf-baseline-2026-10.md` 的现有阈值全部在**竖屏紧凑档手机窗口**采得，只约束紧凑档；同一指标在中等/宽窗口（横屏、平板、折叠展开）不适用该基线，要么按同法重采并单独登记，要么如实标注「该形态无基线」，禁止沿用竖屏数值宣称达标。
- 所有 AI/网络操作必须可取消、带超时且不可阻塞 UI；失败重试不得重复生成学习事件或损坏文章版本。
- 存储空间不足、模型下载中断、资源损坏、数据库迁移失败均应以可恢复错误呈现。

### F5-03 可访问性与兼容性

- 关键流程支持动态字体、深色模式、TalkBack 与 `docs/specs/00` 的窗口类别支持矩阵（紧凑/中等/宽三档，含旋转与折叠不丢状态）：可访问标签、焦点顺序、状态播报、按钮大小和颜色对比度在三档下都成立，导航换摆法不改语义。
- 发音提供播放、暂停、重播和速度调节；无网络/无可用 TTS 引擎时提供文字状态。
- 覆盖有 GMS 与无 GMS 设备的 OCR 降级；覆盖 Android 13+ 通知权限限制。

### F5-04 隐私、许可与发布审核

- 完成每个依赖、词书、词典、音频、Piper 模型、TalkifyTTS/云端服务的许可证、来源、NOTICE、商业使用、再分发和隐私数据流审核。
- 应用内提供“关于与开源许可”页，展示必要声明、链接和第三方服务隐私说明。
- 未核验的非商业模型、强 Copyleft 静态依赖或无授权词书不得进入发布构建。
- 发布说明明确：无账户、无自动云备份、AI 为用户自配、Key 不导出、照片发送第三方前需确认。

### F5-05 加载反馈与进行中语义

（2026-11-07 批 C 补写；口径、证据与红线见 `docs/decisions/2026-11-07-loading-skeleton-shimmer-prefetch.md`。）

- 本地读盘的界面（一级页与其子页）在数据到位前必须画**与真实内容同形状的骨架**，不得只画转圈或一句裸文本，更不得画成「空列表」——空列表与「没有数据」对用户是同一个形状。
- 骨架零文案、零数字：不得向 TalkBack 或视觉播报尚未读到的计数、进度或占位内容（与 `docs/decisions/2026-11-06-placeholder-text-is-not-learning-content.md` 同源）。
- 循环微光（shimmer）只做修饰，不承载信息；其动画周期的**末尾值必须等于静息骨架外观**，使系统关闭动画（`animator_duration_scale=0`）时定格画面就是设计内的静态骨架——应用侧不得为此新增任何降级分支或时长换算。
- 网络 / AI 的等待界面属于另一类：必须给出**进行中语义**（说明正在请求什么、可取消、有超时），不得画成已有结果的骨架或假快照。
- 允许且鼓励真预取，但**预取只能读本地**：不得为了预取新增任何网络或 AI 出站，不得绕过既有的逐次出站确认。

## 验收标准

- AC5-01：每个 `docs/specs/00` 至 `04` 的验收项都关联至少一项自动化测试或可重复的手工测试脚本，并在发布构建中通过。
- AC5-02：离线模式下，词书学习、复习、已缓存文章阅读、离线查词和可用系统 TTS 均可完成；AI 功能给出离线状态而不阻塞 UI。
- AC5-03：TalkBack 能完成选择词书、开始学习、提交三档反馈、查看完成状态、打开历史文章和进入数据管理入口。
- AC5-04：第三方台账无缺项，所有发布资源均通过许可证和商业分发审核；“关于与开源许可”页可访问。
- AC5-05：导出包、日志、崩溃报告和发布构建扫描均未发现 API Key、Authorization Header、明文密码或设备私钥。
- AC5-06（2026-11-07 批 C）：本地读盘界面在数据到位前显示同形状骨架（零文案、零数字）；网络/AI 等待界面显示可取消的进行中语义而非假结果；`animator_duration_scale=0` 下每条骨架规格定格即为设计内静态骨架；预取路径经零出站探针核验，未新增任何网络或 AI 请求。

## 发布阻断条件

- 任一备份验证失败路径会写入正式数据。
- API Key 或密码出现在日志、导出包、截图诊断或业务数据库。
- 未取得词书、词典、模型或音频的发布许可。
- 离线学习、复习或已缓存阅读被 AI/网络失败阻塞。
