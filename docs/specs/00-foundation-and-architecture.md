# 阶段 0：工程基础、离线架构与安全基线 Spec

## 目标

建立可持续迭代的 Android 工程基线，让后续背词、AI、媒体和备份功能能在本地优先、安全可测的边界内开发。

## 范围

### F0-01 工程与架构

- 使用 Kotlin 与 Jetpack Compose 创建 Android 应用工程。
- 采用分层模块边界：`lexicon`、`learning`、`reading`、`language`、`ai`、`backup`、`notification` 与 `ui`；UI 不直接访问网络、密钥或数据库。
- 本地关系数据使用 Room；媒体资源存入独立应用私有目录，并通过资源 ID 和 SHA-256 与数据库关联。
- 建立依赖注入、错误模型、时间/时区抽象和可替换 Provider 接口。

### F0-02 本地数据与安全凭据

- 创建本地 Profile、词书元数据、单词、学习事件、进度、今日计划、文章、媒体和 AI Profile 的 schema 与迁移机制。
- API Key 仅写入 Keystore 支撑的 SecretStore；Room 仅保存不可逆的 key alias/reference。
- 建立日志脱敏规则：Authorization、API Key、图片二进制、备份明文、密码和私钥不得记录。
- 网络信任基线必须由 `android:networkSecurityConfig` 显式声明，不得只靠平台默认：base-config 只列系统信任锚并禁明文流量，
  用户/企业安装的根证书与自签名证书在正式包一律拒；`debug-overrides` 放开用户 CA 只对 debuggable 构建生效，供设备抓包取证。
- SQLCipher 是否启用由基准测试与密钥生命周期设计决定；未决定前不得将数据库裸文件作为备份格式。

### F0-03 可替换服务边界

- `ReviewScheduler`：输入学习状态与反馈，输出新状态与下次复习时间。
- `AiProvider`：声明文本、视觉、语音能力；不向 UI 暴露供应商协议。
- `PronunciationProvider`：统一系统 TTS、端侧模型与云端语音。
- `OcrProvider`：只返回文字、坐标与置信度。
- `BackupProvider`：只接受逻辑快照与媒体清单，不接受数据库文件直拷贝。

### F0-04 依赖与许可台账

- 创建 `docs/third-party-notices.md`，登记所有依赖、数据集、模型的名称、版本、许可证、用途、网络/隐私数据流、NOTICE 位置、替代方案和商业分发结论。
- 未完成许可核验的资源不得进入正式发布包。

## 非功能要求

- 核心本地读写不得在主线程执行。
- 对无网络、存储空间不足、数据库迁移失败和 Keystore 不可用提供可测试错误状态。
- 适配动态字体、深色模式和 TalkBack 基础导航；屏幕形态按「窗口类别支持矩阵」承诺（2026-11-06 批 B 补写，原文只写「适配小屏」，未覆盖横屏、平板与折叠屏）：

  | 窗口类别 | 判定（内容宽度 dp） | 典型设备形态 | 版面承诺 |
  |---|---|---|---|
  | 紧凑 | `< 600` | 手机（竖屏） | 底部四栏导航，单列内容，页头可用 hero 档 |
  | 中等 | `600 ≤ w < 840` | 平板竖屏、折叠屏内屏 | 侧边导航栏取代底栏；内容区收成上限宽度内的单列，慢加载屏优先获得两栏资格 |
  | 宽 | `≥ 840` | 平板横屏、折叠屏展开态 | 侧边导航栏；页头降级为普通页头；主从两栏（列表 + 详情）在已接入的 flow 生效 |

  **进入中等/宽两档的前置条件（2026-11-07 用户裁定，决策 §10）**：`smallestScreenWidthDp ≥ 600`。
  `sw` 取屏幕最小边、与当前旋转无关，所以手机转横屏后 sw 仍是那个短边（实测 1080×1920 @420dpi 的手机横屏
  是 `w731dp h339dp`、sw=339dp），**手机形窗口一律锁竖屏**，中等/宽两档只在平板与折叠大屏上真实出现。
  锁定的落点是资源限定（`res/values/config.xml` 关、`res/values-sw600dp/config.xml` 开）经
  `AppOrientationPolicy` 在两枚生产 Activity 的 `onCreate` 各应用一次；`AndroidManifest` 里不写
  `android:screenOrientation`（它不接受资源引用，写死会把平板一起锁掉）。
  这条限定的实测理由：竖排长列版面在 339dp 高的窗口里不成立——同一批 connected 用例在手机横屏红 35 枚、
  在平板形窗口（`w1080dp h737dp`）只红 5 枚，且红的那 5 枚与形态无关或属判据本身。

  三档一律**同一套导航语义**（同样的四个目的地、同样的 testTag 与朗读标签、同样的选中/未选中状态播报），只换摆法；旋转与折叠不得重置当前 tab 或清空已提交的学习反馈。
- 本矩阵明确**不做**的事：不做桌面/多窗口专属排版与鼠标悬停交互；不做第二套导航语义（宽窗口不新增目的地，也不删目的地）；不为横屏单独设计一套视觉；不承诺所有屏在宽档同时两栏（两栏按 flow 逐个接入，未接入的屏在宽档保持上限宽度内的单列，不拉伸成横条）；**不做手机横屏版面**（sw < 600dp 的横屏窗口不进入用户可见形态，见上一段）。

## 验收标准

- AC0-01：应用离线启动后可创建本地 Profile，重启后仍能读取，且日志中无敏感字段。
- AC0-02：AI Profile 的 Key 只可经 SecretStore 读取；导出 Room 逻辑数据时不存在 Key 明文或 Authorization Header。
- AC0-03：任一 UI ViewModel 不能直接引用 HTTP 客户端、SecretStore 或 Room DAO。
- AC0-04：媒体文件被删除或哈希不一致时，资源读取返回“不可用/可重建”，不导致应用崩溃。
- AC0-05：第三方台账中每一项都具备许可证、用途和数据流字段；缺字段时发布检查失败。
- AC0-06：正式包的传输信任面被配置钉死：`AndroidManifest` 挂 `android:networkSecurityConfig`，其 base-config 的信任锚只有系统根且禁明文；用户根证书只允许出现在 `debug-overrides` 内（仅 debuggable 构建生效），release 不得继承该开口。

## 不在本阶段实现

词书内容、背词 UI、AI 实际调用、文章生成、OCR、提醒和备份恢复。
