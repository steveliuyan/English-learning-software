# 阶段 1：词书、背词与间隔复习 Spec

## 目标

交付离线可用的“选择词书—生成每日计划—词卡反馈—FSRS 复习—解释性完成状态”学习闭环，不依赖 AI 或网络。

## 前置

完成阶段 0 的本地数据、时间抽象和 `ReviewScheduler` 边界。

## 范围

### F1-01 词书与活动词书

- 内置小学、初中、高中、四级、六级、考研词书的元数据及经过许可核验的词条数据。
- 用户可浏览词书名称、等级、词量、进度并选择活动词书。
- 词书选取页不得出现「整页空白后突然满屏」：进入页面即呈现加载占位；册列表（名称、等级、词量）读到即先发布，各册进度逐册回填，进度未到位的册显示占位而不是隐藏整列。词书内容解析与词条索引收敛不得阻塞册列表首帧（决策 2026-10-17 §决定 2）。
- 每个词书独立维护学习进度；切换词书不删除记录。
- 删除本地词书内容前必须说明：可保留学习历史或同时删除该词书历史；默认保留历史。文章因词书删除仍须可读。

### F1-02 今日计划状态机

- 本地日切为设备当前时区的 `00:00`。应用检测到时区/时钟变更时，依据计划 ID、已生成日期和学习事件幂等修复，禁止重复发放新词或丢失到期项。学习日身份由该 profile 最近一次已生成计划（`today_plans` 中 `localDate` 最大者）锚定：设备当前本地日历日不大于该计划日期时不新建、直接复用现有计划快照；仅当本地日历日严格晚于该计划日期时才新建新计划；时区/时钟回退视为同一学习日。
- 首次请求当天学习时固定生成计划快照：`newTarget`、`dueTarget`、计划新词 ID、计划复习 ID、活动词书、规则快照、生成时间。
- 新词目标最小值为 1；词书不足时取实际剩余量。`newTarget=0` 只可由词书无剩余词产生，视为新词条件满足。
- 新词取词顺序为**确定性交错序**，不由词书原始顺序（内置册为字母序）决定：把该册全部卡片按词条**前 3 字母**分组，组内按 `cardId` 的稳定哈希排序，再以「最冷却优先、剩余最多先出」的确定性贪心展开，保证**任意两个同前缀词条的位置差不小于 `floor(n / M)`**（`n`=该册词条总数，`M`=最大的前缀组大小）；等价说法：任意连续 `floor(n / M)` 张卡的前缀互不相同。该顺序由词书内容唯一决定，与传入顺序无关，跨进程、跨设备、跨版本逐位可复现。计划生成时取「该顺序中未学词的前 `newTarget` 个」，因此剔除已学词不改变其余词的相对次序（决策 2026-10-17）。V1 不提供切回字母序的开关：按字母顺序浏览的需求由 F1-07「全部单词」承担。
- 到期复习以计划生成瞬间为准。`dueTarget=0` 时复习条件视为满足；逾期词优先于新词，不因新词目标被挤出。复习卡的先后由排程的 `nextReviewAt` 决定，不受上一条影响。
- V1 不设置复习硬上限；当到期词数量很大时，显示总量、支持分批学习，但未完成的计划复习仍影响严格模式完成。

### F1-03 词卡与反馈（回忆 → 揭晓 → 评分）

- 词卡正面只展示单词、IPA、词性；英文例句有资源时显示，作为回忆的语境线索。英文例句来自随包词书数据里烘焙好的例句（F1-08）；没有例句时整块不显示，不显示占位。中文释义与词形变化默认隐藏，仅在用户点击「显示释义」后展示。
- 流程为先回忆后辨认：用户先在心中回忆词义，点击「显示释义」核对，再提交三档反馈。「显示释义」本身不是学习事件，不计完成度，不改变卡片未完成状态；对未提交反馈的卡片离开并重新进入后，释义回到隐藏状态，需再次揭晓。
- 三档评分按钮（不认识 / 模糊 / 认识）在揭晓前后均保持可见与可提交，避免已确定判断时多一步；每张计划卡在用户提交一次有效反馈后才完成。三档映射为：不认识→Again，模糊→Hard，认识→Good；映射为 V1 固定规则。
- 新增词卡与到期复习卡使用完全相同的回忆-揭晓-评分流程，无差异。
- V1 不提供「直接显示释义」的设置开关，统一采用回忆优先默认（决策见 `docs/decisions/2026-10-14-wordcard-recall-reveal-flow.md`）。
- 每次提交生成唯一事件 ID；重复提交同一 ID 不得重复计数或二次调整间隔。
- 用户可离开学习流程；未提交反馈的卡片保持未完成。V1 不提供撤销已提交反馈，避免排程歧义。
- 调度记录算法版本、参数版本、评分、发生时间、调度前后状态。升级只能重算未来 `nextReviewAt`，不改写事件。

### F1-04 完成与解释

- 严格模式解锁条件：`newDone == newTarget && dueDone == dueTarget`。
- 宽松模式解锁条件：`newDone == newTarget`。
- 计划生成后新到期词不改变计划的 `dueTarget`。
- 每次反馈提交与进入今日页均重新计算状态，显示“新增 x/y、复习 x/y”与未解锁原因码。
- 当日设置改动默认次日生效；仅未提交过反馈的计划可由用户明确重建。

### F1-06 词卡详情页（说明图 + 展示开关）

- 学习流程中，用户提交反馈后可查看当前词卡的详情页，获得比词卡更完整的解释；详情页为**纯查看**页面，不改变完成度与解锁判定。
- 触发规则：三档反馈（认识 / 模糊 / 忘记了）各自受设置中一个独立开关控制。该档开关开启时，提交后进入当前词卡详情页；关闭时提交后直接推进到下一张。三档均提供开关，不做档位限制。
- 开关默认值：模糊 = 开、忘记了 = 开、认识 = 关。理由是"认识"的词不需要额外解释，而"模糊 / 忘记了"正是需要看解释的场景。设置改动立即生效，无需重启。
- 详情页内容模块（V1 全部提供，模块级可配置留待后期设置项）：中文释义与词性、音标、例句、词根 / 记忆法、说明图、文章上下文例句。发音按钮在阶段 3 交付实际音频前不提供。
- **例句模块**取随包词书里的例句（F1-08）；无值时按本节「缺失模块整体隐藏」处理。例句与译文必须成对展示：只有英文、没有译文时不展示该模块的译文行，不伪造译文。
- **说明图**：离线内置，随安装包提供，按单词（lemma）映射；用于以图示辅助理解词义，是解释的补充而非替代。无对应说明图的词条不显示图片区域，不留空位。
- **缺失模块整体隐藏**：任一内容模块无数据时整块隐藏，不显示空标题、不显示"暂无"占位。依赖阶段 2 才有数据的模块（文章上下文例句）在 V1 自然处于隐藏态。
- 详情页的进出不得写入或修改任何学习事件，也不得影响当日计划计数、解锁状态与已提交反馈。
- 「重新学习」仅在调用方提供具体操作时显示；V1 所有入口均不提供，因此不显示（见 `docs/decisions/2026-09-30-learning-records.md`）。

### F1-08 例句的离线烘焙与随包分发

随包十册词书（45,290 张卡）的 `example` 字段实测只有一个取值「暂无例句」（判据见 `ui/WordBookContentPlaceholders.kt`），
用户要求「每本书里所有词都有例句」，并明确要求例句**像原生数据一样长在词书里**，而不是运行时按需生成后再缓存。
因此例句改为在**离线产线**里一次性生成、随包分发：运行时零请求、零缓存、零出站，`WordCard.example` 是界面上唯一的例句取值来源。
裁定与代价（体积、许可、不可在用户侧重生成）见 `docs/decisions/2026-11-11-card-examples-baked-into-bundled-wordbooks.md`。

- 产线输入是用户提供的十册 Excel 原件（与 `v1-xlsx-20261003` 同源）。转换出的词条集合必须与随包资产逐册完全相同，不一致即中止，不产出任何例句。
- 生成单位是**一张卡一个请求**：请求里只含该词的 lemma、词性与中文释义（全部来自词书数据），不含学习记录、笔记、profile 名称或任何其它内容。
- 输出契约是严格 JSON：`{"example": "一句英文，8–16 词", "exampleZh": "对应中文译文"}`。只接受这两个字段，多给的字段一律丢弃。
- 每条结果落盘前必须通过校验：英文句非空、长度 20–160 字符、**必须出现该词或其屈折 / 拼写变体**（括注可选字母按原样或省略均可，如 `vapo(u)r` 接受 vapour / vapor；斜杠并列任一侧即可，如 `axe/ax`；带重音的词条按原样比对，如 `cliché`；词条本身有录入笔误时，放行与之编辑距离为 1 的整词，如 `microsope` 对应 microscope）、不含中文字符、不含 Markdown 标记、句子数不超过 2；译文非空、含中文、长度 4–120 字符。任一不过即判该条失败，重试有上限，超限后记为失败并列出，**不合格内容不得进入任何产出文件**。
- 产出分两段：先写 sidecar `tools/wordbooks/examples/<bookId>.json`（键为 lemma），再幂等合并进 `app/src/main/assets/wordbooks/<bookId>/book.json`。合并**只写 `example` 与 `exampleZh`**，其余字段逐字节不动。
- 产线可被中断：每完成 N 条落一次盘，重跑时已完成的词条直接跳过、不重复请求；同一 sidecar 重复合并的结果不变（幂等）。
- 覆盖率目标是**全量 45,290 张卡**。真的生成不出来的卡保持「暂无例句」，由产线报告逐条列出；这类卡在界面上按 AC1-28 整体隐藏，不显示占位。
- 体积预算：十册 `book.json` 合计不得超过 60MB（当前 41.6MB，例句预计再增 8–11MB）。
- 出处必须登记：`metadata.json` 的 `dataVersion` 递增；决策文档记录模型名、提示词版本与生成日期；第三方台账登记「例句为 AI 生成文本」及其许可判定。
- 例句只在两处进入界面：词卡正面（揭晓前的语境线索）与详情页例句模块。二者都读 `WordCard.example` / `exampleZh` 这一条映射（`WordBookPackageParser` 已接好），不得各写一套回落逻辑。
- 运行时不存在「例句生成失败」这个状态：唯一可能的缺失是资产里没有例句，按「缺失模块整体隐藏」处理；因此本功能不需要成本提示、出站确认、暂停续跑或失败重试界面。

### F1-07 学习记录与词书单词列表

- 首页提供「学习记录」入口，页面含三个标签：今日已学、历史记录、全部单词。
- 今日已学：列出今日计划内已提交反馈的词，按提交时间先后；每行显示单词、首条释义与当时反馈（认识 / 模糊 / 不认识）。
- 历史记录：列出当前 profile 在所有词书下的全部已学词，按学习日分段、最新在前，段标题含日期与词数。学习日以该计划快照的日期为准，不按事件发生时刻换算；同一计划同一词只显示第一次提交。
- 今日尚未生成计划时「今日已学」为空；尚未选择活动词书时「全部单词」为空；两者都只显示一句说明。
- 全部单词：列出当前活动词书全部词，顺序同词书；每行显示单词、首条释义与状态。状态规则：无复习状态为「未学」；下次复习时间不晚于当前时刻为「待复习」；否则为「学习中」。顶部提供「全部 / 未学 / 学习中 / 待复习」筛选并显示各自数量。
- 点击任意一行打开 F1-06 的只读详情页，规则同 F1-06：不写入或修改学习事件，不影响当日计数与解锁。
- 学习记录中词卡已无法解析时（换词书、删词书、包损坏），该行保留并显示 `cardId` 中的单词部分，置灰、不可打开，并说明原因；学习历史不因词书变化而消失。
- 各标签首次选中时加载，切换标签不重复读取；读取在后台线程完成。读取失败显示可重试的错误，不展示半份数据；无数据时只显示一句说明，不留空表头或「暂无」占位。
- 范围外：统计、收藏、错词、查询历史仍属 F4-01；搜索与查词另立规格。

## 验收标准

- AC1-01：首次选词书、设置每日目标后，离线生成今日计划；退出重开后计划及进度不变。
- AC1-02：今日 `newTarget=10,dueTarget=0` 时，严格模式完成 10 个新词即完成；`newTarget=0,dueTarget=5` 时，完成 5 个复习即完成。
- AC1-03：同一初始进度提交 Again、Hard、Good，生成的下一复习时间满足 Again ≤ Hard ≤ Good；保存三条完整学习事件。
- AC1-04：同一事件 ID 重放两次，新增/复习完成数和 `nextReviewAt` 与单次提交一致。
- AC1-05：计划生成后又有单词到期时，该单词不进入已有计划；次日计划才纳入。
- AC1-06：切换到另一词书后原词书进度保留；相同拼写但不同词书的单词默认分别计进各自进度。
- AC1-07：模拟跨日、时区改变和应用重启，不产生重复新词计划或丢失已提交的反馈。
- AC1-07a：设备本地日期回退到早于最近计划学习日时，复用现有计划快照，不新建计划，也不改写旧计划行。
- AC1-07b：设备本地日期与最近计划学习日相同时，复用现有计划快照，不新建计划。
- AC1-07c：设备本地日期严格晚于最近计划学习日时，新建新计划快照（允许跨多日直接新建），旧计划行及其任务保持不变。
- AC1-07d：该 profile 无任何计划时，按首次路径生成今日计划快照。
- AC1-07e：同一物理学习日内改变时区不产生第二个计划，复用现有快照且不重写其 `zoneId` 与生成时间。
- AC1-08：提交「模糊」反馈且设置中「模糊」开关为开时，进入当前词卡详情页；详情页展示该词的中文释义与词性、音标，并在存在说明图资源时展示说明图。
- AC1-09：设置默认值为认识 = 关、模糊 = 开、忘记了 = 开；提交「认识」后不进入详情页直接推进，提交「模糊」「忘记了」后进入详情页。
- AC1-10：在设置页关闭某一档开关后，该档反馈提交后不再进入详情页，改为直接推进；改动立即生效，无需重启。
- AC1-11：进入并退出详情页不改变当日完成度与解锁判定——详情页进出前后「新增 x/y、复习 x/y」与解锁状态一致，且学习事件表中不新增、不修改记录。
- AC1-12：对无说明图资源的词条、以及无数据的任一内容模块，详情页隐藏对应区域，不出现空标题或"暂无"占位。
- AC1-13：三个开关的取值在同一 profile 内持久化，应用重启后保持；不同 profile 之间互不影响。
- AC1-14：完成两天学习后，「历史记录」分两段显示两个学习日，最新在前，每段词数与该日提交数一致；同一学习日内改变时区不拆成两段。
- AC1-15：「今日已学」只包含今日计划内已提交的词，按提交先后排列，反馈与提交时一致。
- AC1-16：「全部单词」的状态满足：无复习状态为未学；下次复习时间等于当前时刻为待复习；晚于当前时刻 1 毫秒为学习中。各筛选数量与对应列表行数一致。
- AC1-17：从三个标签任一行打开详情再返回，学习事件表、复习状态表与当日完成度、解锁状态均不变；打开学习记录前后数据库文件内容一致。
- AC1-18：学习记录中词卡已无法解析的行仍显示单词部分，置灰且不可打开；应用不崩溃。
- AC1-19：详情页在未提供重新学习操作时不显示「重新学习」按钮。
- AC1-20：词卡正面在揭晓前不显示中文释义与词形变化，只显示单词、IPA、词性（及有资源时的英文例句）；点击「显示释义」后展示中文释义，有资源时展示词形变化。
- AC1-21：只点击「显示释义」而不提交反馈时，学习事件表不新增记录，当日「新增 x/y、复习 x/y」计数不变，卡片保持未完成；离开并重新进入该卡后释义回到隐藏状态。
- AC1-22：新增词卡与到期复习卡均按相同的回忆-揭晓-评分流程运行；揭晓前后三档评分按钮均可见且可提交。
- AC1-23：同一词书连续两次求新词取词顺序，结果逐位相同；且输出是输入 id 集合的置换（不丢词、不重复、不新增）。
- AC1-24：取词顺序不等于词书原始顺序，且与传入顺序无关（正序与逆序输入结果逐位相同）；该册中任意两个前 3 字母相同的词条，其位置差不小于 `floor(n / M)`（`n`=册内词条数，`M`=最大前缀组大小）。
- AC1-25：从取词顺序中剔除任意已学词后，剩余词条的相对次序与完整顺序一致（是完整顺序的子序列）；剩余词不足目标时返回全部剩余词，`limit<=0` 返回空。
- AC1-26：词书选取页调用 `load()` 后第一帧即处于加载态（无需等待任何挂起工作）；册列表在全部进度算完之前已可见，进度按册逐条回填。
- AC1-27：词书读取失败时，词书选取页仍显示既有错误文案且不残留半份列表；`refreshIndex` 未被注入（可空依赖）时列表与进度照常发布。
- AC1-28：随包例句为占位串（「暂无例句」）且无缓存时，词卡正面与详情页都不出现例句模块，也不出现空标题或「暂无」字样。
- AC1-29：`book.json` 里该卡带合格例句时，词卡正面（揭晓前）与详情页都显示该英文例句，详情页同时显示中文译文；两处读同一条 `WordCard.example` / `exampleZh` 映射，解析器与占位判定规则不改。
- AC1-30：产线对模型输出缺字段、字段为空、不含该词、含中文、含 Markdown、超长、或非 JSON（含代码围栏包裹但可剥离）时必须给出确定结论：可剥离围栏的合格内容接受，其余一律拒绝且不写 sidecar、不写 `book.json`。
- AC1-31：产线写满第 k 批后被中止，重跑时从已完成处继续、已完成词条不重复请求，sidecar 行数与报告的处理数一致；同一 sidecar 连续合并两次，`book.json` 逐字节不变。
- AC1-32：合并只动两个字段——对十册逐册做字段级快照对比，除 `example` / `exampleZh` 外所有字段与合并前完全一致。
- AC1-33：覆盖率与成对性——十册合计 45,290 张卡中带合格例句的卡达到目标覆盖率（产线报告列出的失败卡除外），任一 `example` 非空必然 `exampleZh` 非空，且每个例句逐条通过 F1-08 的同一份内容规则（资产级棘轮测试读真文件）。
