# 全应用界面排版与人机交互审查（2026-10-25）

审查范围：4 个一级 tab 下的全部 35 个屏/叠层页面 + 底部导航 + 共用组件（页头、入口行、词行、对话框）。
审查依据：逐屏读取 Compose 源码（`app/src/main/java/com/example/englishlearning/ui/`）、2026-10-17 设计稿与设计系统文档、
`docs/verification/ui-redesign-2026-10.md` 已登记口径。**本轮不改代码**，只出清单供拍板。

证据口径：本文每条都带 `文件:行号`。凡涉及「首屏是否可见」的判断是**按 640dp 可视高的结构估算**，
不是像素实测；真机 6.1–6.5 寸通常更宽松，小屏/大字号更紧。属于「需设备侧取证」的条目在 §7 单列。

## 1. 总体判断

### 1.1 好看吗：统一，但平

一致性强：薄荷品牌色、白卡 + 1dp 描边 + 18–24dp 圆角、四档字体、入口行 56dp，全站没有跑偏的屏。
问题在**层级扁平**：几乎每块内容都是「同款白卡 + 同样的 14dp 间距」，一屏 6–8 张同权重卡片，
用户眼睛找不到落点。今日计划的权威数字（完成数）被三张同壳卡包着，主 CTA 在 640dp 屏上压线到折叠线以下
（`TodayPlanScreen.kt:282`，其上方累计约 550dp 内容）。打卡页把同一完成率画了 4 遍
（`CheckInScreen.kt:100/111-121/124-137/139-160`），看起来像数据展示练习，不像用户结论。

**一句话**：不是「乱」，是「没有重点」。

### 1.2 合理吗：功能都在，但一件事有多个说法

- 返回控件有 4 套实现（`AppScreenHeader` / `TextButton("返回")` / `‹` 字形 / 无顶部返回），返回文案 5 种
  （返回、← 返回上一层、← 返回设置、← 返回修改、返回生词本）。用户每进一屏都要重新找出口。
- 「AI 学」有 2 套状态词（`AiLearningScreen.kt:205` 与 `AiFeature.kt:135`），AI 配置里同一个默认服务有 3 个叫法
  （`AiProfileSettingsScreen.kt:237/252`、`AiFeature.kt:85`）。
- 备份区把「导出 / 认证导出 / 受保护导出 / 配对码」四个概念并排放在同一页（`BackupHubScreen.kt:77-92`），
  标题词序还交叉：「认证导出（可用于新设备恢复）」与「从旧设备恢复（认证恢复）」。
- 设置页「备份与恢复」导航行的副标题里塞了「清空学习数据」（`SettingsScreen.kt:408`），
  让破坏性动作与导出同权出现在一句里。

### 1.3 容易上手吗：主线很好，分支很陡

**最强的一条**是核心学习路径：今日计划 → 开始学习 → 词卡三档评分 → 完成。三屏之内闭环，没有分叉，
这是全应用最像成熟产品的地方。

**最容易卡住的四处**：

1. 「我的词」一页三段串在同一个滚动列里（`MyWordsScreen.kt:129-136`），且宿主从不传 `section`
   （`AppScreen.kt:1156` 起），用户点进来永远落在收藏段，想找错词要滚两屏。
2. 阅读页首次打开每篇文章先弹一层覆盖词弹窗（`ArticleReadingScreen.kt:173-216`，
   按 articleId 记忆，首次必弹），把正文推到弹窗后面。
3. 备份区三个入口的差别要靠副标题分辨，而恢复页的密码框还是**明文**（`BackupRestoreScreen.kt:127`
   没有 `visualTransformation`）。
4. AI 配置页 14 个输入/开关（`AiProfileSettingsScreen.kt:306-421`），保存按钮在滚动区最底；
   「官网」字段只存不读（全仓 `websiteUrl` 只在表单、实体、校验中出现，无任何展示消费方）。
